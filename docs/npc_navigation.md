# NPC 목적지 선택·우회·차선 변경

2026-09-03 사용자 요청으로 추가한 **NPC 차량 10대의 규칙 기반 주행 확장**이다.
플레이어 차량의 자율주행/FSD나 NPC 전체 타이어·서스펜션 물리를 구현한 것은 아니다.
보행자 8명은 기존 지정 횡단보도·보행 신호를 그대로 따른다.

## 적용과 지도

`cpp/host/config/signal_city_server.cfg`는 `npc_autonomous=true`를 사용한다.
이때 `npc_route`와 `npc_alternate_route`는 초기 배치 경로이며 이후 주행 경로를 고정하지
않는다. 키가 없거나 `false`인 기존 cfg는 종전 고정 경로 모드를 유지한다.

- `signal_city_v2`: 방향 차선 **58개**, 신호 head **16개**, controller **2개**.
- 8개 접근도로 각각에 **좌회전·직진·우회전 전용 3차로**를 저작했다. 각 차로는 실제
  전용 connector로 이어지며 진입부에서 목적지에 맞는 차로를 선택한다.
  JSON의 선택 항목 `lane_changes`가 대상 lane ID와 source/target 시작·끝 arc station을 지정한다.
  **3.2m 차로 폭·3.3m 중심 간격**이며 중앙 차로에서 양옆으로, 바깥 차로에서는 중앙으로
  변경할 수 있다. 변경은 진입부 fan과 정지선 앞을 제외한 지정 직선 구간에 한정한다.
- 외곽 연결도로 3001~3004는 입구·출구 약 12m를 도로 방향과 접선이 이어지는 cubic로
  연결한다. 단순 endpoint 삽입으로 발생하던 역방향 짧은 구간과 급격한 yaw 변화를 제거했고,
  기존 도로·합류부 지면을 유지한다. 이 보완은 실제 충돌 반작용과 정상 경로 회전을 구분하는
  서버 처리와 함께 사용한다.
- 저장 `.umap`과 지면·연석도 백업 후 함께 갱신했다. 최신 맵·MapPackage·서버·traffic
  sidecar를 함께 사용하며, 이전 한 차로 맵의 표시만 남겨둬서는 안 된다.
- 현재 map checksum: `fnv1a64:86c3103f3e2c7a5b`.
  traffic checksum: `fnv1a64:b19c15afba6936d7`.
  이 identity는 package preflight로 확인한 값이며 전체 인수 완료 선언이 아니다.

## 주행 결정

1. **목적지 선택:** 현재 위치에서 도달하고 다시 다른 주행으로 이어갈 수 있는 연결 영역에서
   신호 없는 목적지 lane을 선택한다. 25m 이상 도로를 짧은 connector보다 우선하며 막다른
   종점은 반복 주행 목적지에서 제외한다. entity ID·trip counter로 결정하므로 같은 초기
   조건과 입력은 같은 선택을 만든다. 도착 시 다음 목적지를 선택한다.
2. **경로·우회:** 저작된 directed `successors`만 따라 거리 기준 최단 경로를 계산한다.
   선택 경로 전방 최대 **80m**에서 정적 충돌체와 정차한 Ego/독립 proxy를 확인하고,
   막힌 미래 lane을 제외해 **같은 목적지**로 다시 탐색한다. 정차 기준은 평면 속도
   0.3m/s 미만이다. 정상 신호 대기열·정상 보행자는 일시적인 주체로 구분하되,
   사고로 정지한 NPC와 넘어진 보행자는 실제 충돌 형상으로 도로 폐쇄 검사에 포함한다.
   현재 점유 lane을 건너뛰거나 미저작 연결·임의 U-turn을 만들지 않는다.
3. **차선 변경:** 앞길 방해가 지속되고 저작된 같은 방향 이웃 lane에 안전한 간격이 있을 때
   변경을 시도한다. 정지한 사고차·고정 장애물은 일반 대기열의 추가 대기 없이 검토한다.
   기본 길이 `max(12m, 현재 속도[m/s] × 2.5s)`의 quintic 곡선을 우선하며, 저속에서는
   남은 합법 구간·앞차 위치에 맞춰 최소 `max(8m, 현재 속도[m/s] × 2.5s)`까지 검토한다.
   전체 차체와 곡선 끝점까지 기존 충돌·간격 검사를 통과해야 하며 목적지는 유지한다.
4. **너무 가까운 장애물 회피:** 앞차에 가까이 붙어 8m 변경 곡선을 만들 수 없으면 먼저
   정지한 뒤 현재 차선 안에서 최대 6m를 1.4m/s 이하로 후진한다. 후방 경로와 1m 정지
   여유를 0.25m 간격으로 검사하며, 뒤 차량이나 구조물이 있으면 후진하지 않는다. 공간을
   만든 다음 목적지·사고 차선·인접 차선 간격을 다시 평가하고 합법적인 차선으로 통과한다.
   교차로를 역주행하거나 저작되지 않은 연결을 만드는 기능은 아니다.

판단은 0.25초마다 현재 신호, 동적 장애물, 사고·폐쇄 차선, 인접 차선 간격과 목적지를 다시
확인한다. 따라서 초기 경로를 그대로 재생하는 방식은 아니지만, 범위는 저작된 lane graph와
근거리 충돌 검사 안으로 한정된다. 카메라·라이다 등의 센서 인식이나 자유공간 자율주행은 아니다.

경로 교체는 현재 위치·lane offset·속도·누적 주행거리와 유효한 신호 진입 허가를 보존한다.
녹색에 이미 진입한 교차로의 connector를 중간에 바꾸지 않는다. 목적지 도착은 lane 끝에서
차량별 앞끝 길이와 정지 여유 0.5m를 뺀 지점의 정차로 판정한다.

NPC ID 순서로 `sedan → compact → truck → motorcycle` 프로필을 반복 배정한다. 각 프로필은
차체 OBB 크기, 질량, yaw 관성, 최고속도, 가속·제동 한계를 따로 사용한다. 정지 거리와 차선
변경 지면/간격 검사도 해당 차체 크기를 사용한다. 이는 차종별 서버 주행·충돌 차이를 위한
축약 모델이며, 각 NPC에 Ego와 같은 타이어·서스펜션 강체 물리를 실행한다는 의미는 아니다.

## 안전·실패 경계

- 목표 차선 앞뒤 차량에 기본 2m 여유와 **2초 headway**, 접근 속도 차이에 대한
  **3초 closing TTC**를 요구한다. 회전한 OBB의 차선 방향 투영 크기도 반영한다.
- 변경 곡선 전체를 **0.25m 간격**으로 지면·정적 충돌·Ego·NPC·보행자 proxy와 검사하고,
  다른 NPC가 이미 예약한 변경 경로와 겹치면 시작하지 않는다.
- 이동 중에도 기존 전방 충돌 가드와 신호 제약을 적용한다. 완료 시 저작된 lane pair,
  station 대응, 같은 신호 그룹·주행 방향과 지면 지지를 다시 확인한다.
- 변경 표본 또는 최종 target adoption이 실패하면 **해당 tick의 follower 진행을 rollback**하고
  마지막 표시 pose와 속도 0을 보존한다. 숨은 진행 누적이나 옆 차선으로의 순간이동으로
  복구하지 않는다. 합법 경로/안전한 간격이 없으면 정지·대기하며 무리하게 통과하지 않는다.
- 이는 작은 코스용 보수적 규칙 AI다. 실제 센서 인식, 교통 수요·군중 회피, 복잡한 교차로
  협상, 연속 시공간 충돌의 수학적 보장, NPC full vehicle dynamics는 포함하지 않는다.

## 충돌 후 정지·복귀 (9/3 후속)

충돌 반작용을 표시하면서 내부 경로는 계속 전진하고, 짧은 hold 뒤 offset을 지수 감쇠하던
방식이 빠른 원위치 복귀의 원인이었다. 현재는 NPC와 보행자의 경로 진행을 멈추고
`Settling → Holding → Recovering → Driving`으로 처리한다.

- 밀려난 운동이 멎은 **그 위치에서 2~5초** 대기한다. 접촉이 계속되면 즉시 복귀하지 않는다.
- 회복 가능한 충격은 **최대 0.35m/s, 가속도 0.25m/s²**로 서서히 경로에 복귀한다.
  NPC 방향 복원도 최대 8도/s로 제한하며, 이동 중 지면이나 충돌 검사가 실패하면 대기한다.
- 강한 충격 또는 누적 손상 100%는 `Disabled`로 자동 운행·원위치 복귀를 중단한다.
  유한질량은 유지하므로 다른 차량에 밀리는 물리 반작용까지 고정하는 것은 아니다.
  **새 Play/reset**에서 초기화된다.
- 강도는 250ms 동안의 normal impulse/mass로 판단한다. 반응 시작 0.15m/s,
  단일 강충격 4m/s 기준은 **충돌로 인한 속도 변화량**이지 차량의 주행 속도 제한이 아니다.
  이는 데모 조정값이며 실제 파손/부상 예측이 아니다. NPC 전체 타이어·서스펜션
  동역학으로 확장한 것은 아니다.

### 충돌 기울기·전복과 사람형 표시

NPC에 `ImpactTumbleState`를 추가했다. 충돌 방향·충격량과 차종별 범퍼 접촉 높이로
pitch/roll 각운동량을 계산하고, 상자형 차체의 지지점 관성·중력·면 착지 시
에너지 손실로 흔들림과 전도를 처리한다. 약한 충격은 직립으로 정착하며, 충분히 강한
충격은 옆면 또는 지붕으로 넘어져 자동 주행·원위치 복귀를 중단한다. 새 Play로 복원한다.
접촉마다 강제로 뒤집는 연출이 아니므로 평범한 저속 접촉은 전복되지 않는다.

기울어진 상자의 지지 높이와 보수적인 yaw-aligned 충돌 외곽을 같은 서버 tick에 갱신한다.
기존 wire의 pitch/roll·body angular velocity를 사용하고 UE 차량 모델의 크기·로컬 중심은
고정한다. 이는 **지면에 구속된 간이 강체 모델**이며 공중 비행, 정밀한 6자유도 OBB 접촉,
NPC 전체 타이어·서스펜션 계산, 부품 파손을 새로 구현한 것은 아니다.

보행자는 UE 5.6 기본 **Manny/Quinn 사람형 마네킹**을 사용한다. 에셋 출처는 Content의
`ASSET_PROVENANCE.md`에 기록했다. 서버 횡단 방향으로 body X를 맞추고 속도에 따라 걷는다.
새 횡단은 WALK 잔여 시간이 `횡단 거리 / 1.35m/s + 0.2초` 이상일 때만 시작한다.
도착 직후 남은 짧은 WALK에 반대편으로 재출발하지 않으며, 이미 횡단 중인 사람은 RED로
바뀌어도 도로를 끝까지 벗어난다. 상시 GREEN 계획의 잔여 시간 0은 무기한 허용으로 처리한다.

충돌 이벤트는 물리 계산이 끝난 **같은 WorldState tick**에 전송한다. `PedestrianImpactState`는
충격량에 따른 수직 속도와 전도, 중력, 지면 지지, 회복 가능한 경우의 일어서기를 계산한다.
서 있는 동안의 capsule(radius 0.35m, half-height 0.9m)은 넘어지면 **하나의 낮은 OBB로 교체**한다.
원치수 half-length/width/height `0.25/0.35/0.95m`의 자세 투영을 사용하므로 완전히 누웠을 때는
`0.95/0.35/0.25m`가 된다. 기존 upright capsule을 남겨 보이지 않는 벽을 만들지 않는다.

`PositionEnu`는 실제 몸통/골반 근사 중심, `LinearVelocityEnu.Z`는 수직 속도다. `pedestrian_downed`와
`pedestrian_airborne`은 별개 상태이며 비행 중 둘 다 참일 수 있다. UE는 이를 기준으로 몸통과
관절 표현을 맞춘다. 관절별 정밀 충돌을 서버에서 계산하는 전신 동역학/부상 예측은 아니다.

Ego 적분의 최대 0.1m 이동 microstep 안에서 NPC↔보행자 등 유한질량 pair를 함께 해결한다.
별도의 receiver contact로 양쪽 반작용·이벤트를 전달하고, 이 충격을 Ego의 피해로 기록하지 않는다.
충돌 후의 외력 이동은 route obstacle 검사에서 취소하지 않지만 자동 원위치 복귀의 지면/장애물
검사는 유지한다. NPC 차선 변경·예정 회전의 좌/우 의도도 서버가 결정하여 깜빡이로 전송한다.
명목 주행의 yaw는 유한 강체 각속도 한계(4πrad/s) 안에서 먼저 보간한다. 경로 접선의 급변을
solver가 잘랐다는 이유만으로 충격 각속도를 누적하지 않으며, 실제 접촉 충격에 따른 회전은
그대로 반영한다. 급한 polyline 접선에서도 무충돌 차량의 yaw가 정상 방향으로 수렴하는
host 회귀 테스트로 이를 확인한다.

서버 로그 `[Collision] entity=... state=settling/holding/recovering/disabled`로 상태를 확인한다.
가벼운 접촉 뒤 공간을 비워 정지·복귀를 확인하고, 강한 충돌 뒤에는 새 Play 전까지
자체 주행을 재개하지 않는지 확인한다. 몸체 상태·wire 계약을 함께 변경하므로 서버와 UE를
동일 버전으로 빌드해야 한다. 지도 변경 여부와 재생성 절차는 Signal City 실행 안내를 따른다.

## 확인 방법

[Signal City 실행 안내](./signal_city_quickstart.md)대로 서버와 `L_SignalCity`를 연다.
서버 로그의 `[NPC] destination`, `detour`, `lane-change begin/complete`로 결정을 구분한다.
`lane-change safety stop`은 안전 검증 실패로 정지한 경우다. 실제 PIE에서는 도착 후 새
행선지, 적색 정지/녹색 재출발, 정차 차량 앞 안전 변경, 틈이 없을 때 대기를 확인한다.

자동 회귀 소스는 `npc_route_planner_test.cpp`, `npc_lane_follower_test.cpp`,
`npc_lane_change_test.cpp`, `npc_navigation_host_test.cpp` 및
`scripts/test_smoke_signal_city.py`다. 저장소 루트에서 실행한다.

```powershell
ctest --test-dir cpp/host/build -C Release -R 'npc_.*tests' --output-on-failure
python -m unittest discover -s scripts -p test_smoke_signal_city.py
python scripts/smoke_signal_city.py --preflight-only
python scripts/smoke_signal_city.py
```

Signal City wire smoke는 기본 autonomous cfg를 그대로 사용하며 모든 저작 차선 중심선과
정확한 차선 변경 station band만 허용한다. 기존 3cm 경로 허용치를 넓히지 않고, 실제
band 내부의 횡이동에만 최대 10% 속도 여유를 둔다. fixed 모드는 원래 두 경로 검사를 유지한다.
최종 빌드·자동 검증 결과는 [9/4 작업일지](./worklogs/2026-09-04.md)에 별도로 기록하며,
사용자 PIE·목표 PC 성능·30분 안정성 인수는 자동 테스트와 구분한다.
