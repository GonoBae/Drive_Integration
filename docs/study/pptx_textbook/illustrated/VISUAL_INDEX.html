단원별 설명 그림

41개 단원의 그림을 바로 찾아볼 수 있습니다. 그림 옆의 읽기 순서를 확인한 다음 해당 단원의 코드와 예제로 이어가세요. 단원 제목 아래에는 이 내용을 배우는 이유를 적었습니다.

01권 공통 기초와 Protobuf

L01 W 입력 한 개의 왕복과 함수 읽기

입력·계산·표시의 책임을 먼저 나누어야 카메라나 메시지 형식만 고치며 원인과 다른 곳을 수정하는 일을 줄일 수 있습니다.

  • 왕복 그림을 읽는 기준 (9쪽)

L02 프로세스, 이벤트 루프와 콜백

실행 단위를 구분해야 다른 프로세스의 주소를 보내거나, 콜백 안의 긴 계산이 자동으로 다른 스레드에서 실행된다고 오해하지 않습니다.

  • 콜백 등록과 실행이 이어지는 시간선 (25쪽)

L03 선언, 참조, 포인터와 값 없음

출력 포인터를 무조건 사용하거나 지면 질의 실패를 높이 0으로 바꾸면 유효하지 않은 정보를 실제 상태처럼 계산하게 됩니다.

  • 원본, 내부 복사본과 값의 존재 (39쪽)

L04 빌린 메모리의 수명과 공유 입력 잠금

값의 존재 여부와 함께 사용 시점의 수명·동시 접근을 확인해야 읽기 전용이라는 이유만으로 안전하다고 착각하지 않습니다.

  • 값 복사와 빌린 메모리의 비유 (47쪽)

L05 TCP, WebSocket과 직렬화의 역할

통신 통로와 데이터 형식을 분리해야 프레임 분할 문제를 Protobuf 필드 문제로 오해하지 않습니다.

  • 통신 계층 그림의 읽는 순서 (62쪽)

L06 IDL, 생성 코드와 물리 단위 계약

필드 번호와 저장 타입뿐 아니라 실제 의미를 함께 읽어야 컴파일·파싱 성공 뒤에 남는 단위 오류를 찾습니다.

  • 공통 스키마로 값의 의미를 복원 (73쪽)

L07 태그와 varint를 손으로 해석하기

태그와 varint의 구조를 알면 알 수 없는 필드를 건너뛰는 이유와 잘린 정수·범위 초과를 거부하는 이유를 코드로 설명할 수 있습니다.

  • 비트 조각을 연결하여 150 쓰기 (92쪽)

L08 float, UTF-8과 중첩 메시지의 길이

비트 패턴 보존과 바이트 길이를 이해해야 타입 변환과 직렬화, 문자열 길이와 메시지 경계를 혼동하지 않습니다.

  • 안쪽 메시지의 범위와 문자열 바이트 수 (109쪽)

L09 바퀴 목록과 payload 선택

목록의 필드 번호, 원소의 위치 식별값, 메시지 종류 선택을 구분해야 수신 순서나 숫자의 모양에 의존하지 않습니다.

  • 바퀴 위치 식별과 메시지 종류 선택 (123쪽)

L10 값의 부재, 기본값과 스키마 호환성

부재와 명시적 값의 차이를 보존하고 구 수신기의 한계를 이해해야 필드 추가가 기존 운전을 조용히 바꾸지 않습니다.

  • 필드 부재와 명시적 값, 건너뛰기의 한계 (136쪽)

L11 Hello, 지도, 연결과 Play의 구분

연결이 열렸다는 사실만으로 같은 기능·세계·실행이라고 가정하지 않도록 각 식별 정보의 목적을 나누어 배웁니다.

  • Play와 연결의 서로 다른 생명주기 (149쪽)

L12 ControlLease가 오래된 운전을 막는 방법

현재 입력을 보내는 주체에게만 제한된 시간 동안 제어를 맡기고, 지연된 명령이나 무입력 상태를 별도 기준으로 처리해야 합니다.

  • 입력 시각과 무입력 기간의 구분 (163쪽)

L13 한 입력의 왕복과 종합 실습

부분 지식을 전체 경로에 연결해야 파싱 단위 검사가 실제 연결 수락까지 검증했다고 과장하지 않고 문제 위치를 찾아갈 수 있습니다.

  • 검증을 통과한 입력에서 화면의 상태까지 (182쪽)

02권 C++ 서버와 차량 시뮬레이션

L01 실행 파일에서 한 번의 틱까지

설정 읽기·객체 조립·반복 계산을 나누어야 시작 실패와 주행 실패를 구별할 수 있습니다.

  • 시작 준비가 끝난 뒤 이벤트 루프가 틱을 호출합니다 (11쪽)

L02 고정 dt와 두 개의 시간

화면 프레임·물리 틱·실제 경과시간을 분리해야 지연을 정확히 계산할 수 있습니다.

  • 물리 틱 한 번의 시간과 실제 기다린 시간은 다릅니다 (22쪽)

L03 제어권과 오래된 입력을 구별하기

누가 보낸 입력인지와 지금도 사용할 만큼 신선한 입력인지를 별도로 검증해야 합니다.

  • 새 입력의 검증과 입력 부재의 만료를 따로 읽습니다 (37쪽)

L04 상태 큐와 비동기 버퍼의 수명

실시간 상태에는 제한된 대기 정책이 필요하고 비동기 메모리는 완료까지 살아 있어야 합니다.

  • 최신 대기는 교체해도 전송 중인 버퍼는 보존합니다 (51쪽)

L05 지면 측정과 서버 질의의 계약

클라이언트의 충돌 표면과 서버의 읽기 전용 질의가 같은 좌표·범위를 사용해야 합니다.

  • 격자 표본에서 바퀴 아래 접점을 찾기 (65쪽)

L06 접촉이 힘으로 바뀌는 서스펜션

접촉 위치·압축량·압축 속도를 힘으로 연결해야 차량 높이와 접지력을 설명할 수 있습니다.

  • 바퀴별 지지력이 차체를 받치는 모습 (78쪽)

L07 구동·후진과 연석에서 사라진 토크

엔진 요구를 힘·바퀴 토크·접지 한도로 나누어야 멈춤 원인을 찾을 수 있습니다.

  • 바퀴가 뜨면 구동 토크는 어떻게 달라질까요? (95쪽)

L08 조향각·타이어 힘·차체 회전을 연결하기

바퀴가 향한 각도와 접지 힘으로 생긴 차체 회전을 나누어야 주행 원인을 설명할 수 있습니다.

  • 한 타이어가 나누어 사용하는 종·횡방향 힘 (107쪽)

L09 외형과 물리 프로필이 함께 바뀌는 차종

질량·치수·출력·관성과 접촉 구조를 명시해야 차종별 차이를 계산과 연결할 수 있습니다.

  • 차종 선택은 외형과 물리 자료를 함께 연결합니다 (117쪽)

L10 충돌 형상에서 밀림과 회전까지

충돌 형상·상대 속도·유한 질량·접촉점 모멘트를 분리해야 자연스러운 반응을 설명할 수 있습니다.

  • 무게중심에서 벗어난 접촉이 만드는 회전 (132쪽)

L11 목적지 경로와 신호를 따르는 NPC

목적지 선택·도로 경로·추종 제어·국소 공간·표현을 나누면 잘못된 책임을 수정하지 않을 수 있습니다.

  • 경로 선택과 신호 앞 감속은 서로 다른 판단입니다 (149쪽)

L12 가까운 장애물 우회와 틱별 탐색 예산

우회 가능 공간과 탐색 비용을 함께 관리해야 물리 안전과 조작 신선도를 지킬 수 있습니다.

  • 회전하는 차체가 필요한 공간 (161쪽)
  • 후진으로 공간을 만든 뒤 우회하는 개념 (165쪽)
  • 한 번의 긴 탐색을 여러 틱으로 나누기 (171쪽)

L13 화면 재생과 물리 재실행의 증거

기록 대상과 실행 조건을 구별해야 수정 전후를 같은 실험으로 비교할 수 있습니다.

  • 저장 상태를 보여 주는 재생과 물리를 다시 푸는 검증 (181쪽)

L14 혼자 작성하는 재현과 진단 보고서

관측·가설·검사·한계를 문장으로 구분해야 도움 없이 원인을 좁힐 수 있습니다.

  • 같은 시점의 증거에서 검증 가능한 진단으로 이어 갑니다 (195쪽)

03권 Unreal 5.6 클라이언트

L01 W를 눌렀는데 누가 차를 움직이나요?

담당 경계를 모르면 화면 오차를 물리 수식으로 고치거나 서버 문제를 메시 위치로 가리게 됩니다.

  • W 입력이 화면에 돌아오는 왕복 (12쪽)

L02 차체와 바퀴가 함께 움직이는 구조

부품 관계와 좌표 기준을 알아야 각 부품을 일관되게 움직이고 안전하게 참조할 수 있습니다.

  • Pawn과 부품의 역할 (22쪽)

L03 Play를 반복해도 이전 실행이 남지 않게 하기

기본 구조·실행 초기화·매 프레임 갱신·종료 정리를 분리해야 반복 실행이 안전합니다.

  • Play 정리와 새 실행의 경계 (35쪽)

L04 W와 S를 가속·제동·기어로 해석하기

키 이름과 실제 운전 의도를 분리해야 진행 방향에 맞는 제동과 기어 변경을 만들 수 있습니다.

  • 같은 S도 차량 상태에 따라 뜻이 달라집니다 (47쪽)

L05 짧은 조향과 최신 명령을 전달하기

키의 이진 값을 시간 기반 명령으로 바꾸고 오래된 명령이 줄 서지 않도록 최신 값을 보관해야 합니다.

  • 조향 변화와 최신 명령 보관·송신 (63쪽)

L06 명령을 바이트로 보내고 안전하게 받기

데이터 형식·버퍼 수명·실행 스레드·메시지 경계를 각각 지켜야 정상 결과를 적용할 수 있습니다.

  • 받은 바이트가 안전한 상태가 되는 과정 (77쪽)

L07 연결된 서버가 같은 맵과 Play인지 확인하기

통로가 열리고 파싱이 성공했다는 사실만으로 현재 실행의 결과라고 판단할 수 없습니다.

  • 연결 뒤에도 맵·Play·순서 관문이 남습니다 (83쪽)

L08 다음 상태가 잠깐 오지 않으면 화면은 어떻게 움직이나요?

화면을 즉시 끊기게 하지 않으면서도 오래된 속도로 벽을 통과하는 허구의 이동을 그리지 않아야 합니다.

  • 새 패킷이 없어도 화면 프레임은 계속됩니다 (98쪽)

L09 서버의 위치를 Unreal의 차체 위치로 바꾸기

단위와 좌표 기준을 계약대로 바꾸지 않으면 정상 물리 상태도 잘못 표시됩니다.

  • 동·북 축 교환과 단위 변환 (112쪽)

L10 보이는 도로와 계산하는 지면을 맞추기

노면 측정·서버 계산·메시 표시를 구분해야 외형을 옮겨 실제 접촉 오류를 가리지 않습니다.

  • 도로 표면 측정에서 서버 접촉까지 (127쪽)

L11 바퀴의 위치·조향·굴림을 따로 계산하기

허브 위치·조향 방향·굴림 회전은 다른 값이므로 같은 회전 하나로 처리하면 서로 간섭합니다.

  • 월드 접촉점과 자식 부품의 상대 위치 (144쪽)

L12 시야를 가리지 않는 HUD와 돌아보는 카메라

차량 상태를 읽게 하면서도 도로를 볼 공간을 보존하고 카메라 조작의 단위를 맞춰야 합니다.

  • HUD 화면 좌표와 카메라 시선 기준 (163쪽)

L13 소리와 램프의 시작·유지·종료를 정하기

효과는 단순히 재생하는 것이 아니라 실제 상태를 전달하므로 올바른 조건과 수명이 필요합니다.

  • 상태를 파형과 음량으로 바꾸는 구성 (171쪽)

L14 기록과 검사로 스스로 이해를 확인하기

재현 가능한 상태·조건·판정 기준이 있어야 관찰을 근거로 바꾸고 혼자 다음 문제를 조사할 수 있습니다.

  • 기록 재생과 검사로 관찰을 근거로 바꾸기 (196쪽)
