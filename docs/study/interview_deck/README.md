# Drive Integration 면접 핵심 교재

[면접 핵심 PPT 열기](B:/Portfolio/Drive_Integration/docs/study/interview_deck/output/DriveIntegration_Interview_Visual_v2.pptx)

기존 세 권의 교재에서 Unreal 클라이언트 면접에 연결되는 내용을 골라 50쪽으로 묶었습니다. 모든 페이지에 주제와 연결되는 그림이 있으며, 20쪽에는 프로젝트의 실제 코드 발췌를 함께 넣었습니다. 2026년 9월 8일 코드와 작업 기록을 기준으로 작성했습니다.

## 읽는 순서

| 페이지 | 주제 | 설명할 수 있어야 하는 내용 |
| --- | --- | --- |
| 1–3 | 학습 안내와 전체 구조 | Unreal과 서버가 맡은 일, 입력부터 화면까지의 흐름 |
| 4–15 | C++·통신 기초 | 소유권, 비동기 수명, Protobuf, 메시지 검증, 세션과 시간 기준 |
| 16–29 | Unreal 클라이언트 | Actor·Component, GC, 입력, 스냅샷 표시, 재연결, 좌표 변환, 지면·카메라·소리 |
| 30–41 | 서버와 시뮬레이션 | 고정 시간 간격, 최신 상태 큐, 접지·구동·충돌, NPC 경로와 탐색 비용 |
| 42–48 | 문제 해결과 검증 | 기록·재생, 지면 아래로 내려간 차, 트럭 충돌 상자, 연석 재출발, NPC 회전, 성능 측정 |
| 49–50 | 면접 답변 연습 | 하나의 입력 흐름과 문제 해결 사례를 근거·한계까지 설명하기 |

처음에는 순서대로 읽고, 복습할 때에는 **16–29쪽 → 42–50쪽 → 4–15쪽 → 30–41쪽** 순서로 보시면 됩니다. 클라이언트 면접에서는 먼저 표시·입력·객체 수명·좌표계와 직접 관찰한 문제를 설명하는 데 집중합니다.

## 한 페이지를 공부하는 방법

1. 위쪽 질문을 읽고 그림만 보면서 먼저 답해 봅니다.
2. 오른쪽의 **왜 필요한가**와 코드 또는 그림 읽기를 확인합니다.
3. 아래쪽 답변과 비교해 빠진 이유·조건·한계를 찾습니다.
4. 꼬리 질문에 답한 뒤, 더 필요한 설명은 PowerPoint의 **노트**에서 읽습니다.

발표자 노트에는 보충 설명, 현재 코드 원문과 파일 위치, 원교재 권·챕터, 공식 문서 출처를 넣었습니다. 슬라이드의 코드는 읽기 좋게 줄바꿈한 발췌이며, 노트에는 해당 범위의 원문을 보존했습니다. 원교재의 `L01` 같은 표시는 해당 권의 수업 번호입니다.

마지막에는 PPT를 보지 않고 49쪽의 입력 흐름을 설명하고, 43–46쪽에서 한 사례를 골라 **증상 → 원인 → 수정 선택 → 검증 → 남은 한계** 순서로 말해 보세요. 이해하지 못한 부분은 외운 답변으로 덮지 말고 원교재와 해당 코드를 다시 확인합니다.

## 그림과 설명을 읽을 때

- 원리 그림은 교육용 개념도이며 실제 게임 화면이나 실측 성능 그래프가 아닙니다.
- 45쪽은 사용자가 제공한 **수정 전 오류 화면**입니다. 수정 결과는 별도의 재현 시험 기록과 구분했습니다.
- 실차 물리 전체, 모든 NPC 상황, 최신 패키지 장시간 성능까지 검증된 것으로 설명하지 않습니다.
- 면접 답변 예시는 실제 이해와 수행 범위에 맞춰 바꿉니다. AI 보조와 본인이 수행한 요구사항 정의·재현·검증·코드 작업을 구분해서 설명합니다.
- 이 자료는 현재 프로젝트를 설명하기 위한 면접 교재입니다. C++·알고리즘·Unreal 면접 전체 범위를 대체하지는 않습니다.
