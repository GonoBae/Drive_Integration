## 3. 개발 일정과의 관계

8월 20~31일 개발 일정은 8일·64시간을 이미 모두 사용한다. 따라서 8월 학습은 별도 시간을 추가하지 않고 기존 `문서·로그`와 `다음 날 준비` 안에서 회당 30분만 사용한다.

- 8월에는 읽기, 손 추적, Quiz, Teach-back만 수행한다.
- 학습을 위한 production 코드 변경은 Core RC 이후로 미룬다.
- 해당 날짜의 개발 마일스톤이 실패하면 학습 세션을 자동 이월한다.
- 8월 목표는 S00과 S01 완료뿐이다. S02 이후를 억지로 앞당기지 않는다.
- R1 이후 주 3회·회당 90분을 40시간 개발 주간에 포함하면 실제 기능 개발 가능 시간은 주 35.5시간이다.

## 7. 공통 완료 기준

다음을 모두 만족해야 단계를 완료한다.

1. 파일 책임을 한 문장으로 설명한다.
2. 입력·상태·출력·불변식 표를 작성한다.
3. 정상 흐름과 실패 흐름을 하나씩 손으로 추적한다.
4. 노트 없이 3분 Teach-back을 수행한다.
5. Quiz 80% 이상을 달성한다.
6. 관련 시험이 막는 실제 장애를 설명한다.
7. 변경형 단계는 failing test→최소 수정→전체 회귀를 확인한다.

전체 과정에서 최소 5개의 직접 작성한 시험을 증거로 남긴다.
