물리와 표현의 범위는 구분합니다. 차량은 자체 4접점 축약 모델이며 오토바이의 실제 이륜 균형은
구현하지 않았습니다. NPC는 도로 그래프와 주변 상태를 이용하는 규칙 기반 판단이고, 자유 공간의
자율주행은 아닙니다. 보행자의 이동 경로는 횡단보도 중심입니다. 차체 dent는 표시 메시 변형이며
금속 파괴나 변형된 차체 충돌체 계산은 아닙니다. 보행자 ragdoll에는 Unreal 표시용 엔진 물리를
사용하지만 차량 계산과 이동 상태의 권한은 서버에 유지합니다.

세단 외 플레이어 차체는 기능 검증용 모델입니다. 세단용 실내·운전자를 다른 차종에 그대로
표시하지 않습니다. 원경 지면과 스카이라인은 화면의 끊김을 가리는 비충돌 배경이며 실제 주행
영역을 넓힌 것은 아닙니다.

## 후속 구현: 카메라·접속 설정·Windows 패키지

사용자 요청대로 구현 중간에 플레이를 요청하지 않고 작업 후 검증을 모아서 진행합니다.
이번 변경은 표시·실행 설정·배포 범위이며 서버의 차량 물리나 도심 맵은 바꾸지 않았습니다.

- `V`/패드 왼쪽 스틱 클릭으로 외부 추적→운전석→차량 기준 고정 후방을 전환합니다.
  `C`/오른쪽 스틱 클릭은 항상 기본 후방 추적으로 복귀합니다. 추적 시점만 줌을 허용하고,
  운전석은 시선 회전 범위를 제한하며 고정 후방에서는 회전·줌 입력을 무시합니다.
- 운전석은 차종별 위치와 차체 자세를 따릅니다. 세단 운전자 몸이 카메라를 가리지 않도록
  플레이어 시점에서만 숨기며 실내는 남깁니다. 트럭은 불투명 운전실 모델이므로 차체 앞
  시점으로 대체해 안내합니다. 다른 차종 실내나 독립 자유 이동 카메라는 추가하지 않았습니다.
- 클라이언트는 기본값→`SimCoreClient.ini`→`-SimCoreServerUrl` 순서로 설정을 적용합니다.
  기본 INI 위치는 Unreal ProjectDir이며 `-SimCoreClientConfig`로 다른 파일을 지정합니다.
  map 상대 경로는 INI 위치 기준입니다. R1은 `ws://127.0.0.1:<port>/` 또는
  `ws://localhost:<port>/`만 지원하고 재실행해야 설정이 반영됩니다.
- 명시한 파일 누락, 잘못된 값, 중복·알 수 없는 키는 연결을 차단하고 HUD에 원인을 표시합니다.
  차종 변경도 잘못된 설정을 우회할 수 없으며 WebSocket에 빈 URI를 전달하지 않습니다.
- `package_windows.ps1`이 매번 새 배포 폴더를 만들고 UE 게임·서버/DLL·지도·설정·실행기를
  묶습니다. 문자열로 불러오는 차량·캐릭터를 Cook 대상에 넣고 `Config/sensors.json`은
  별도 JSON 파일로 배포합니다. 기존 출력이나 사용 중인 서버를 임의로 삭제·종료하지 않습니다.

[Windows 제작·실행 방법](../windows_package.md)을 추가했습니다. 새 카메라·설정 회귀와
패키지 구성 검사를 작성했으며 검증 실행 결과는 이 절 아래에 기록합니다.

- 최종 패키지 제작: **통과**. UE 5.6 Win64 Development의 build/cook/stage/archive와

  실행했으므로 현재 폴더에 의존하지 않는 설정 경로 처리도 확인했습니다.
- 테스트용 서버 PID 25528과 게임 PID 22940만 종료했습니다. 기존 9000 서버 PID 22016은
  그대로 유지했습니다. 화면 렌더링·조작감·다른 위치/PC 배포·30분 주행은 수행하지 않았습니다.

완성 폴더:

```text

```

그 안의 `StartClient.ps1`로 게임을 실행합니다. 기존 9000 서버가 실행 중이면
`StartServer.ps1`를 중복 실행하지 않습니다. 다른 PC에서는 폴더 전체를 옮기고
[Windows 실행 안내](../windows_package.md)에 따라 서버부터 실행합니다.

## 후속 수정: 차로 합류 표시와 사고 보행자 우회

사용자 피드백 두 건과 관련 코드 정리만 대상으로 삼았습니다.

- 차로 합류: 직선 3차로의 내부 구분선은 직선 끝에서 끝나고, 곡선 연결도로에는 중앙선과
  가장자리 선만 남아 있었습니다. 3차로가 1차로로 줄어드는 과정이 보이지 않는 원인입니다.
  기존 공유 중심곡선을 기준으로 내부 구분선이 순서대로 가장자리 선에 합류하도록 보완했습니다.
- 사고 보행자 우회: NPC가 차선 변경 허용 구간을 지나 멈추면 기존 후진 한도 6m로는
  우회를 시작할 공간까지 돌아가지 못했습니다. 또한 경적 정책은 쓰러진 사람을 다른 정차
  장애물과 구분하지 않아 같은 사람에게 반복 경적을 울렸습니다.

도로·보도·차량 물리·메시지 형식의 재설계는 포함하지 않습니다. 기존 작업 파일과 검증
이력은 보존하며, 실제 화면의 차선 연결과 사고 상황별 주행은 자동검사와 구분해 확인합니다.

구현 내용:

- 네 접속부 양방향에 내부 구분선 두 개씩, 총 16개 합류선을 추가했습니다. 직선 끝 6m부터
  연결하고 바깥 구분선은 약 12m, 안쪽 구분선은 약 24m에서 기존 가장자리 선에 닿습니다.
  반대 방향에서는 차로 분기로 보입니다. 선폭은 일정하며 도색에 충돌체를 추가하지 않았습니다.
- 쓰러진 보행자 앞에서 공간 확보가 필요한 경우에만 후진 후보 상한을 6m에서 16m로
  늘렸습니다. 항상 최대 거리까지 후진하는 것이 아니라, 실제 우회가 가능한 최소 거리를
