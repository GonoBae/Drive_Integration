## 현재 제약과 위험

- 물리는 평면 2D 종방향+bicycle 1단계이며 강체 6DoF, 타이어 슬립, 서스펜션, 경사, 충돌은 아직 없다.
- 현재 60Hz 타이머는 절대 deadline 기반 `SimulationClock`이 아니다.
- C++ host는 WebSocket binary Protobuf로 ControlCommand를 받고 WorldState를 직접 broadcast하지만 저장소에 Unreal client 구현이 없다.
- Envelope의 sequence와 simulation time은 구현됐지만 command timeout, 재연결 handshake, map checksum 검증은 아직 없다.
- Python relay의 JSON WebSocket은 observer/debug 경로로 남아 있으며 수동운전 runtime protocol로 취급하지 않는다.
- macOS ARM64만 검증했으며 Windows x64 빌드와 목표 PC 성능 시험이 필요하다.
- Windows PowerShell 스크립트는 추가했지만 현재 Mac에 PowerShell이 없어 Windows 실기 검증은 아직 하지 않았다.
- 기준 차량과 파라미터 출처가 아직 확정되지 않았다.

## 일정 영향

- D1에 예정된 물리 접근 결정과 함께 WP-01 Proto 일부, WP-02 기본 종방향·조향 일부를 선행했다.
- 외부 SDK 대신 자체 구현을 선택해 WP-02의 검증 책임과 일정 위험은 증가했다.
- 상세 타이어·서스펜션·충돌을 확장하기 전에 고정 시계와 Unreal 직접 왕복을 먼저 통과해야 한다.
- 실제 작업 시간은 별도 타이머를 사용하지 않아 미계측이다. D2부터 시작·종료 시간과 차단 시간을 기록한다.
