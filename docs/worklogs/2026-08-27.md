# 2026-08-27 작업일지

## control lease 1008 중단 수정

- Unreal은 약 66FPS로 진행했지만 WorldState가 59~60Hz에서 24~40Hz로 먼저 저하된 뒤
  queue-age 거부와 1008 timeout이 발생한 로그를 대조했다.
- 서버 단일 `io_context`의 매-tick 동기 stderr와 소비되지 않는 자동화 pipe가 network
  read까지 막을 수 있는 경로를 확인했다.
- overrun 로그를 최대 1Hz의 `total/delta` 요약으로 바꾸고
  `run_landscape_server.ps1 -Background`가 stdout/stderr를 `runtime_logs/`로 분리하도록
  했다.
- 250ms에는 즉시 SafeStop만 적용하고 같은 session의 fresh command로 복구하며, 1초
  연속 단절에서만 retire·1008 close하는 2단계 lease를 구현했다. stale queue command와
  다른 session의 soft-window 선점은 계속 차단한다.

## 일반 승용차 조작감 수정

- 0.5m/s 미만에서 횡타이어 힘을 0으로 만들던 cutoff를 제거하고
  최종 `low_speed_slip_reference_mps=1.5` regularization으로 저속 횡/yaw 감쇠를 유지했다.
- 목표 횡가속도 3.2m/s²로 최대 road-wheel angle을 제한하고 조향 증가 0.8rad/s·복귀
  1.25rad/s rack rate를 적용했다. 키보드 full input이 즉시 32°를 요구하지 않는다.
- 기본 RWD 구동력 6000N, 후진력 3600N, 100kW power cap, 종타이어 강성
  90000N/slip, 마찰계수 1.05,
  yaw inertia 2850kg·m²와 Drive/Reverse driveline drag 45N/(m/s)를 적용했다.
- strict 차량 설정은 format v4로 올리고 powertrain rise/fall, 횡력 우선 비율,
  traction-control slip 범위와 공중 휠 감쇠를 loader·validation·checksum에 포함했다.

## 후진·휠 표시·저속 트랙션 보완

- 기존 S 입력은 Drive의 service brake만 보내 Reverse를 선택할 수 없었다. S를 계속
  누르면 전진 중 먼저 제동하고, fresh authoritative state에서 거의 정지를 확인한 뒤
  Reverse throttle로 전환하도록 수동 입력 경로를 보완했다.
- 후진 중 W도 같은 안전 규칙으로 먼저 제동한 뒤 정지에서 Drive로 전환한다. W+S 동시
  입력은 throttle을 0으로 두고 제동하며, 상태가 없거나 stale이면 기어를 바꾸지 않는다.
- Unreal 표시 휠은 비접촉 바퀴를 차축 평균에서 제외하고, 접촉 휠의 물리 각속도를
  `signed speed / tire radius`의 ±3%(최소 ±0.10rad/s) 범위로 제한한다. 후진 회전 부호를
  보존하고 정지·stale 상태에서는 0으로 고정해 출발 순간의 과도한 헛바퀴 표현을 없앴다.
- 저속에서 종·횡력이 friction circle을 함께 요구하면 한계의 95% 안에서 횡력을 먼저
  보존하고 `sqrt((mu*Fz)^2-Fy^2)`로 남은 종력 범위를 계산한다. 키보드 가속과 조향을
  함께 입력해도 차체가 옆으로 흐르기보다 노면을 붙잡는 응답을 우선한다.
- 구동륜 slip 8%부터 토크를 줄여 12%에서 완전히 개입한다. 구동축 한쪽이라도 접지를
  잃으면 양 half-shaft 토크를 차단하고 공중 휠은 3.6N·m·s 감쇠로 정지시킨다.
- full throttle 목표 구동력은 18000N/s로 증가하고 36000N/s로 감소한다. 6000N 최대
  구동력까지 약 0.33초가 걸려 키 입력이 한 프레임짜리 힘 충격이 되지 않는다.

## 급경사 차체 부유·접촉 상실 최종 수정

- 연속 평면 정량 probe에서 30°·40° 종경사는 앞바퀴 두 개만, 40° 횡경사는 한쪽 두
  바퀴만 접촉했다. contact point의 지면 높이는 정확했으므로 exporter가 아니라 차체
  mount projection과 suspension/heave 계산, UE wheel 표현을 원인으로 좁혔다.
- 기존 mount 계산은 수평 wheelbase·track은 고정한 채 높이에만 pitch·roll을 반영해 3D
  축이 직교하지 않았다. 이를 orthonormal body forward/right/up basis로 바꾸고 모든 mount와
  body-up suspension을 같은 basis에서 계산한다.
- 접촉은 지면의 실제 tangent patch를 기준으로 하며 wheel center는
  `patch + normal * tire_radius`로 계산한다. 경사에서 수직 ray 기반 근사 때문에 반대 축이
  full droop을 넘는 현상을 제거했다.
- 정지 brake·handbrake가 경사 중력을 상쇄하는 static tire reaction을 force와
  pitch·roll moment에 반영한다. 속도만 0으로 고정하면서 차체를 경사 아래로 기울이던
  불일치를 없앴다.
- 차체 heave는 실제 spring·damper 힘으로 적분한다. 마찰 원용 equilibrium tire load를
  heave에 재사용해 비관통 보정 높이가 영구 고정되던 경로를 제거했다.
- reset은 ground normal로 차체를 먼저 정렬하고 그 자세에서 높이·네 contact·spring
  history를 초기화한다. 수평 pose로 먼저 차체를 들어 올린 뒤 경사 자세를 적용하지 않는다.
- Unreal은 unit-scale root와 별도 visual mesh 구조로 바꾸고, non-uniform scale을 상속하던
  고정 wheel 위치 대신 서버 contact point·normal·tire radius로 네 wheel pivot을 배치한다.
  따라서 서버 접촉과 화면 타이어 위치가 같은 기준을 사용한다.

## 네 바퀴 지지면 기반 차체 자세 보완

- 각 wheel pivot만 지면을 따라가고 차체는 contact normal 평균만 따라가던 한계를
  재현했다. 서로 다른 높이의 수평 발판 네 개는 모든 normal이 수직이므로 기존 계산에서
  차체 pitch·roll이 0으로 남았다.
- `patch + normal * tire_radius`로 복원한 네 wheel center를 차량 yaw 좌표계에서 평면
  적합한다. 이 support plane은 reset pose와 진단에만 사용하고 runtime 차체를 당기는
  attitude 목표로 쓰지 않는다.
- terrain normal basis는 중력·주행·타이어 계산에만 남겼다. wheel 높이 지지면과 분리해
  높이가 다른 수평 발판에서 가상의 경사 중력이나 수평 이동이 생기지 않는다.
- wheel별 실제 spring·damper 반력과 mount arm으로 roll/pitch moment를 계산한다. tire
  load와 heave도 같은 네 반력이 결정하며 quasi-static load table이 이를 덮어쓰지 않는다.
  차체 자세는 네 서스펜션 반력과 차체 관성으로 연속적으로 움직인다.
- chase camera는 차체와 같은 pitch·roll을 상속하지 않는 spring arm으로 바꿨다. 위치와
  yaw는 계속 추종하면서 화면에서 차체가 실제로 기울어지는 정도를 확인할 수 있다.

## 차체 반대 기울기·보이지 않는 경계·4-corner 구조 수정

- UE에서 FLU positive roll을 다시 음수로 바꾸던 이중 반전을 제거했다. protocol
  `angular_velocity_body`는 Euler derivative 묶음이 아니라 true right-handed FLU vector다.
  scalar `yaw_rate`는 navigation Euler rate가 아니라 vector의 true body-Z component다.
  compound attitude에서는 C++가 Euler coupling을 포함해 publish하고 UE가 vector와 현재
  pitch·roll에서 navigation yaw·pitch·roll rate를 재구성해 extrapolation한다.
- 세계각 및 ground-relative pitch `±6°`·roll `±8°` hard clamp를 제거했다. legacy
  `attitude_spring_n_m_rad`, `attitude_damping_n_m_s_rad`는 v4 key로만 남기고 validation에서
  반드시 0을 요구하며 solver moment에서는 완전히 제외했다.
- 각 wheel의 contact normal로 local tangent forward/right를 만든다. massless hub의
  `CG velocity + yaw×arm`을 world에서 그 tangent로 투영해 slip을 구하고 tire force도 같은
  평면에 둔 뒤 common solver basis로 되돌린다. 이 world force의
  `tau_i=(contact_patch_i-CG)×F_i`를 body roll/pitch 축에 투영한다. rolling resistance만
  별도 CG-height lever를 쓰며 중력·공력·driveline drag는 제외한다.
- suspension compression hard-stop position은 `q={z,roll,pitch}`에서 반복당 0.15m·2°
  trust region으로 최대 32회 풀고 잔차만 최소 pure-Z lift로 해소한다. correction 뒤 contact를
  다시 질의하는 outer pass는 최대 4회다. pitch Jacobian은 Euler horizontal-right axis와
  roll-dependent generalized inertia를 사용한다. velocity LCP는 최종 clearance가 activation
  slop 안인 corner만 활성화하고 accumulated unilateral impulse를 32회 교대 sweep한다.
- roll/pitch dynamics는 finite-angle generalized axes/inertia, `E-dot*qdot`, gyroscopic
  `omega×(I*omega)`와 planar yaw acceleration coupling을 포함한다. full 6DoF는 아니며
  planar XY/heading, massless hub·1D suspension, airborne/unsprung/tire carcass 부재라는
  reduced-model 한계를 유지한다.
- `Ground Actor` 전체 component bounds와 기본 100cm padding에 sampling box를 맞추는
  `Fit Sampling Bounds To Ground Actor` Editor 버튼을 추가했다. tracked CSV는 아직
  `east=-15~15m`, `north=-7~30m`이다. 당시에는 wheel ray 1~3개를 모두 partial support로
  허용하고 centre query miss 또는 wheel ray 0개에서만 fail-closed해 첫 wheel이 범위를
  벗어날 때 생기던 보이지 않는 벽을 제거했다. 이 정책은 2026-08-28 terminal footprint
  회귀에서 완전 axle/side loss도 fail-close하도록 보완됐다. 재-bake 전 package의 최종
  coverage 범위 자체는 유지된다.

벽 수동 게이트를 완료했다는 뜻은 아니다.
