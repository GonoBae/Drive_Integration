## 첫 작업: 문서 동기화

2026-09-02에 완료한 전체 리팩터링과 최종 통합 검증을 문서 중앙 색인과 현재 상태 설명에
일관되게 반영했다. 이 첫 동기화는 문서 정합화이며 코드, MapPackage, Unreal asset, 물리 수식과
프로토콜 계약을 변경하지 않는다.

## 확정된 리팩터링 결과

- C++: runtime option facade/cfg/CLI, traffic hot reload, Protobuf encoder/decoder,
  `SimulationHost` session 처리를 분리했다.
- Unreal: 세단 시각 계약, 입력 resolver, client diagnostics, replay format/runtime,
  NPC·보행자와 traffic signal presentation을 분리했다.
- Windows 실행: Signal City, Virtual City, Landscape wrapper가 공통 launcher의 파일·port
  검증, background 로그, PID 소유권과 readiness 검사를 사용한다.
- 공개 Proto, MapPackage/traffic schema, UCLASS/subobject/input action, cfg 우선순위와
  fixed-tick lifecycle 의미는 유지했다.

통합 중 collector 차선의 비연속 heading이 큰 NPC 각속도를 만들고, 공통 collision
substep의 적분 시간을 줄여 무관한 보행자 속도까지 오염시키는 문제를 발견했다. 유한질량
OBB 입력 각속도를 기존 `±4π rad/s` 상한으로 제한하고, 164rad/s 입력이 있어도 별도
보행자가 정확한 60Hz 이동량을 유지하는 회귀를 추가했다. Signal City smoke의 기존
순항속도·경로 허용치는 넓히지 않았다.

## 후속 요청: 오늘 일정의 자동 작업 실행

사용자 요청으로 9/3 행의 Core 자동 통합, replay 결정성, 성능 측정 도구를 진행했다.
새 배경/차량 아트나 주행 물리 튜닝으로 범위를 넓히지 않았으며 기존 F3/F5/F6/Space 입력,
공개 Proto, 차량 cfg와 맵·에셋은 유지했다. 첫 절 이후의 최신 상태는 아래가 기준이다.

### 1. 실제 입력 기반 Ego 물리 재생

- `--record-physics <새 파일> --record-ticks N`이 서버에서 실제 적용한 fixed-tick
  `VehicleInput`, lifecycle/reset, update 직전 동적 collision proxy와 결과 상태를 기록한다.
- 화면 좌표만 다시 보여 주는 F6 ghost와 별개로, `--verify-physics-replay`가 동일
  실행파일 bytes checksum·vehicle checksum·collision checksum·origin/spawn/Hz를
  확인하고 같은 `VehiclePhysics`를 다시 실행한다.
- 모든 frame의 위치 ≤1cm/yaw ≤0.1도와 body/wheel/damage 관측값을 검사한다.
- 로그에만 쓰던 `last_logged_input_`는 0.001 이하 입력 변화가 생략될 수 있으므로,
  정확한 `applied_input_`를 별도 보존했다. 물리 입력 자체나 수식은 변경하지 않았다.
- format/유한값/순서/완료 footer/count/checksum/중복 proxy를 엄격히 검사한다.
  최대 216,000frame·1GiB를 적용하고 기존 출력 파일 덮어쓰기를 거부한다.
  올바른 footer checksum으로 다시 서명한 malformed fixture도 거부하는 회귀를 추가했다.
- map/traffic reload는 기록을 무효화한다. 강제 종료로 잘린 파일도 정상으로 승인하지 않는다.

범위는 **기록된 외부 충돌 입력을 사용하는 Ego 물리 재현**이다. RESET 외 lifecycle은
marker이고, 그 효과는 각 tick의 실제 적용 입력으로 재현한다. lease FSM, NPC/보행자 AI,
AgentIntent와 전체 traffic logic 자체를 offline에서 재실행하는 것은 아니다.

### 2. opt-in 성능 캡처와 분석

- `-SimCorePerfCapture`로 켠 경우에만 엔진 frame-end 간격과 승인된 WorldState의
  game-thread 도착 간격을 메모리에 기록하고 종료 시 CSV/JSON을 저장한다.
- 기본 warmup10초/duration60초이며 mode·실제 viewport·VSync/fps cap/fixed step/
  smoothing·설정 변경·완료 이유를 기록한다. GPU 단독 처리 시간이나 입력 인과 지연은 아니다.
- `analyze_performance.py`는 누락/NaN/잘린 CSV/중복 metadata/구간 불연속을 거부한다.
  packaged 1920×1080·uncapped·30분 및 수치 조건이 충족되어야 measurement gate를
  인정하고, 수동 주행·안정성·입력 최초 변화 50ms는 항상 별도 미검증으로 남긴다.
- 실제 smoke에서 매 frame CVar 검색 경고를 발견해 포인터만 cache했다. 값은 계속 읽으므로
  측정 중 설정 변경 감지는 유지된다.

### 3. 통합 검증 실행기

`scripts/check_core.py --engine-root <UE_5.6>`가 15단계의 build·CTest·Proto·Python·
launcher·wire/replay·UE Automation·두 맵/traffic ValidateOnly를 수행한다. 실패 시 중단하고
단계별 로그와 보고서를 보관한다. 시험 0개/완료 개수 불일치/skip을 전체 통과로 간주하지
않는다. `--skip-build`/`--skip-unreal`은 `partial_pass`, preflight는 미실행으로 구분한다.
기존 사용자 서버는 종료하지 않고 wire 시험은 생성한 임시 port 자식 서버만 정리한다.

### 4. 실제 실행에서 발견한 재접속 맵 경로 오류

서버를 켜지 않은 `UnrealEditor-Cmd -game` smoke에서 재접속마다 상대 프로젝트 경로가
붙어 길어졌고, 끝내 `collision payload not found`로 manifest 검증이 실패했다.
원인은 `FPaths::ProjectDir()`도 상대 경로일 수 있는데 이를 그대로 두 인자
`ConvertRelativePathToFull`의 base로 사용한 것이다.

프로젝트 base를 먼저 절대 경로로 만든 뒤 package를 해석하도록 수정했다. 순수 경로
변환 10회, 실제 manifest 3회 검증을 포함한 Automation을 추가했다. 수정 후 7초짜리
offline 실행에서도 모든 재시도는 동일한 `B:/Portfolio/Drive_Integration/map_packages/signal_city_v2`
경로와 checksum을 유지했다. 서버가 없는 상태의 socket 연결 실패는 이 시험의 예상 조건이며,
map 검증 실패나 CVar 반복 검색 경고는 없어졌다.

## 후속 요청: NPC 목적지 선택·우회·차선 변경

사용자가 고정 경로 설명 후 세 기능 추가를 승인했다. NPC 차량 4대에 한정해
서버 규칙 AI를 확장했으며, 보행자는 기존 횡단보도 경로를 유지한다.

- `NpcRoutePlanner`: directed successor 거리 최단 경로, 같은 연결 영역 안의 재방문 가능한
  목적지 선택. entity ID/trip counter가 같으면 같은 선택을 한다. 도착 후 다음 목적지를 선택한다.
- 호스트: 전방 80m의 정적/정차 장애물이 막은 미래 차선을 제외하고 같은 목적지로 우회한다.
  신호 대기 차량·보행자를 도로 폐쇄로 해석하지 않으며, 합법 경로가 없으면 대기한다.
- `NpcLaneChangePlan`: 명시된 같은 방향 차선 사이를 최소 12m의 quintic 곡선으로 연결한다.
  앞뒤 간격·접근 속도, 전체 이동 경로의 OBB/지면 검사와 다른 변경 경로 예약을 적용한다.
- 변경 완료 시 위치·속도·거리와 목적지를 보존해 target lane으로 인계한다. 지면 또는
  최종 검증 실패 시 내부 진행을 되돌리고 마지막 pose에서 정지한다. 허용 구간 끝에는
  한 tick의 초과 이동 여유를 남겨 영구적인 인계 실패를 방지한다.
- `npc_autonomous=true`가 Signal City 기본값이며 기존 두 loop는 spawn 배치에 사용한다.
  옵션이 없거나 false인 기존 cfg의 고정 route 동작과 공개 wire schema는 유지한다.

## 후속 요청: 충돌 위치 유지·심한 충격 시 운행 중단

사용자 PIE에서 충돌로 밀려난 NPC가 곧바로 원래 경로로 미끄러져 돌아오는 문제가 확인됐다.
18-tick hold 뒤 offset을 지수 감쇠하는 동안 내부 follower는 계속 진행해, 충돌 위치에서
정지하는 상태가 없었다. 복귀 속도를 다시 충돌 잔여 속도로 저장하는 되먹임도 제거했다.

- 서버 `ImpactRecoveryState`를 추가했다. 250ms normal impulse/mass 창으로 강도를
  분류하고 `Settling → Holding → Recovering → Driving`, 강한 충격은 `Disabled`로 처리한다.
- 충돌 시 경로·차선 변경 진행을 동결하되 실제 잔여 운동은 감쇠하며 유지한다. 정착한
  위치에서 2~5초 대기한 뒤, 회복 가능한 경우만 최대 0.35m/s·0.25m/s²로 복귀한다.
  NPC heading 복원도 최대 8도/s·5도/s²로 제한한다.
- 심한 충격(속도 변화량 4m/s 이상) 또는 누적 손상 100%는 자동 복귀·자체 운행을 중단한다.
  외부 충돌로 밀릴 수 있는 유한질량은 유지한다. 새 Play/reset에서 복원한다.
- 속도 변화량은 주행 속도가 아니며 이 기준은 **데모 튜닝**이다. 실제 차체 파손 역학,
  NPC 타이어/서스펜션 전체 동역학, 보행자 ragdoll을 새로 구현한 것은 아니다.
- 서버 로그에 entity별 `settling/holding/recovering/disabled` 전환을 남긴다.
  클라이언트·wire·지도 포맷은 바꾸지 않아 이번 변경만 적용할 때 UE 재빌드나 Bake는 없다.
- NPC·보행자의 복귀 구간을 지면과 장애물에 대해 검사한다. 막혔을 때 실제 위치·경로
  진행을 보존하고 복귀 완료로 처리하지 않는다. 보행자는 정지 pending proxy를 유지해
  복귀가 막힌 상태에서도 새 외부 충격은 반영한다.

자세한 동작과 확인 방법은 [NPC 경로 판단](../npc_navigation.md#충돌-후-정지복귀-93-후속)을 따른다.
PIE 체감 인수와 전체 Core 완료 여부는 기존의 미완료 항목으로 유지한다.

## 후속 요청: NPC 전도·전복과 사람형 보행자

사용자는 단순 평면 밀림을 넘어 충돌에 의한 기울기/전복과 사람 형태의 보행자를 요청했다.

- 외부 물리 SDK 없이 `ImpactTumbleState`를 추가했다. NPC가 받은 반대방향 normal impulse,
  범퍼 접촉 높이, 상자 지지점 관성·중력·착지 에너지 손실로 pitch/roll을 계산한다.
  강제 flip 애니메이션이 아니며, 약한 충격은 흔들림 후 직립하고 충분한 에너지의 충격은
  측면/지붕으로 넘어져 유지된다. 넘어지면 이전 경로로 자동 복귀하지 않는다.
- 기울기에 따른 지면 지지 높이와 보수적 yaw-aligned OBB 외곽을 실제 collision snapshot에
  반영한다. 처음 통합에서는 resolved proxy가 새 높이/외곽을 덮어쓰는 문제가 있어,
  solver 입력에 accepted envelope를 넣어 수정했다. ±π 경계의 잘못된 360도 sweep도
  shortest-angle 보간으로 수정했다.
- 기존 EntityState pitch/roll·angular_velocity_body를 사용한다. 기울어진 자세의 body

- UE 차량은 충돌 외곽 크기에 따라 늘어나거나 로컬 중심이 이동하지 않는다. 전복 중에는

## 후속 요청: 구조물 충돌 피해

사용자 승인에 따라 건물 외벽 부분 손상과 신호등 기둥 전도·고장을 구현했다.
외부 물리 SDK와 건물 전체 붕괴는 추가하지 않았다.

- 서버 `StructureDamageRuntime`이 Wall 접촉의 충격량과 기둥 피해를 계산한다.
  250ms 접촉 구간 최대 충격량으로 약한 지속 압력의 무한 누적을 막는다.
- 기존 비충돌 신호등에 서버 runtime pole proxy를 추가했다. 충격량·봉의 관성·중력·
  감쇠로 힌지 전도하며, 쓰러진 외곽을 물리와 wire에 같은 tick 기준으로 반영한다.
  기둥은 차량 접촉 시 무한질량 proxy다. 자유 강체·실제 재료 파괴 해석은 아니다.
- 파손된 head는 소등하고 해당 controller 전체는 적색·잔여시간 0을 유지한다.

- UE는 건물 접촉 부위에 균열·표면 손상과 1.8초 비충돌 파편을 표시한다.

## 후속 피드백: 재충돌·보행 방향·래그돌·국부 파손 6건

사용자의 실제 Play 피드백을 받아 다음 누락/오동작을 수정했다.

1. 사고 차량 재밀림: `Settling/Disabled` 외력 이동이 Ego 장애물 검사에서 취소되던
   경로를 수정했다. 자력 복귀에는 기존 검사를 유지한다. 사고 뒤에도 유한질량을 유지하고
   후속 충돌 이벤트를 발생시킨다. 실제 충돌→정지→후진→재충돌과 운동량 유지 시험을 추가했다.

   -90도 모델 보정을 분리하고 네 방향의 body velocity/Actor 전방을 검사했다.

이번 요청의 네 항목만 수정한다. 맵·신호 계획·차량 수·자산은 변경하지 않는다.

- 낮게 쓰러진 신호등/보행자에는 둥근 축약 표면과 원형 타이어의 접촉점·법선을 구한다.
  지면 지지·높이·이동 속도·차륜 경로/하부 여유를 검사하고, 타이어/서스펜션으로 앞뒤
  바퀴가 차례로 올라가게 한다. 기존 지면이 없는 곳을 동적 물체로 메우지 않는다.
  공중 물체·높은 물체와 차륜 사이에서 하부보다 높은 물체는 충돌을 유지한다.
- 신호등의 무한 질량 충돌이 먼저 차량을 정지시키던 순서를 제거했다. 기초부의 남은
  저항 충격량을 소진한 뒤 동일 microstep에서180kg 물체와 잔여 충격을 교환한다.
  방출된 신호등의 이동·회전을 유지하고 지면 마찰로 감속한다. NPC 충돌도 같은 구조물
  피해 처리에 연결하며 SafeStop에서는 움직이지 않는다. 새 Play는 원래 배치를 복원한다.
- 보행자의 기존 수평 충격 비례 수직 발사를 제거했다. 접촉 높이와 질량중심의 차이로
  각충격량을 계산해 하체/상체 접촉의 회전 방향을 구분한다. 실제 겹치는 보닛/유리/지붕
  근사 표면에 위에서 닿았을 때만 지지한다. 지지 중인 차량 한 쌍의 중복 평면 충돌만
  제외하고 바닥 밑에서 지붕으로 올리지 않는다. UE 팔다리 속도도 선속도+각속도에서
  유도하며, 기존15m/s 제한을60m/s로 바꿔 고속 차량보다 느리게 강제로 묶지 않는다.
- NPC 교착을 실제 호스트에서 재현했다. 옆 차로가 빌 때까지 기다리며 사고차 뒤0.74m까지
  접근하면 변경 경로를 만들 수 없었다.8m 조향 여유를 보존하며 기다리고 안전한 계획을
  시작할 때만 예약 정지점을 해제한다. 추가 polling 없이 기존1초 간격을 유지하며
  대기 이유가 바뀔 때만 로그를 남긴다. 같은 테스트에서 수정 전12초 정지, 수정 후
  `1010 → 1015` 차선 변경 완료를 확인했다. 후진 탈출/없는 인접 차로 생성은 범위 밖이다.
- 새 내부 충돌 필드를 물리 기록의 optional `CONTACT` 확장에 보존한다. 기존 확장이 없는
  기록도 읽으며, 재생 시 타이어 지지·기초부 저항·지지 차량 정보를 잃지 않게 했다.

모델의 범위: 자체 유한 질량/축약 몸통·기둥/차량 표면 계산이다. 실제 금속 기초부 파괴,
전신 관절의 서버 충돌, 사람을 타이어가 누르는 연체 변형까지 구현한 것은 아니다.
