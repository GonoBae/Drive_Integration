## collector 커브 차선 교차 수정

Signal City의 네 collector 전환부에서 중앙선과 가장자리선이 커브 중간에 서로 꼬이는
원인을 생성 수식에서 확인했다. 전환부는 직선 끝에서 `-StraightForward` 방향으로
진행하지만, v2 시작점의 좌우 offset은 반대 방향 frame의 `+StraightRight`를 그대로
사용했다. 반면 collector 끝점은 진행방향 frame을 사용했기 때문에 같은 `Side` 값의
좌우 순서가 곡선 양 끝에서 뒤집혔고, cubic 표시선이 중앙선을 가로질렀다.

시작점 offset을 실제 테이퍼 진행 frame에 맞춰 반전하고, 기존 v2 결과를 정확히 재현하는
`BuildNaturalLaneMarkingsV2Layout()`을 별도로 보존했다. 새 생성 상태에는
`SimCore.SignalCity.AlignedCollectorMarkings.v3` tag를 사용한다. 저장 맵 갱신 commandlet은
현재 맵이 정확한 v2 생성 상태인지 먼저 확인하고, 일치할 때만 백업한 뒤 소유한 비충돌
노면 표시 geometry를 v3로 교체하도록 구성했다. 사용자 actor나 수동 편집 geometry는
덮어쓰지 않는다.

수정된 수식을 네 전환부 전체 구간에서 연속 검사한 결과 표시선 교차는 없었다. 가장자리와
중앙선의 최소 간격은 WS 3.468m, ES 3.526m, WN 3.650m, EN 3.625m였다. 같은 검사에서
보존한 v2 수식은 네 곳 모두 기존 교차를 재현해 migration 원본 비교가 실제 문제 상태를
가리키는 것도 확인했다. `DriveIntegration.SignalCity.CollectorLaneOrdering` 회귀를
추가했고 Signal City 자동 검사 11개를 통과했다.

실제 저장 맵에도 보호 migration을 적용했다. 적용 전 맵과 MapPackage는
`unreal/DriveIntegration/Saved/Backups/SignalCityTraffic-20260905-004709-24898154`에
보관했다. 적용 후 `-ValidateOnly`가 오류·경고 없이 통과했으며 collision identity는
`fnv1a64:86c3103f3e2c7a5b`, traffic identity는 `fnv1a64:b19c15afba6936d7`로
그대로 유지됐다. 이번 변경은 비충돌 노면 도색만 교체했으므로 58 lanes, 신호 head 16개와
지면·정적 충돌 데이터는 바뀌지 않았다.

## 플레이어 차종 선택

플레이어도 주행 중 네 차종을 선택할 수 있도록 다음 입력을 추가했다.

| 입력 | 차종 |
|---|---|
| `1` | 세단 |
| `2` | 경차 |
| `3` | 트럭 |
| `4` | 오토바이 |

다른 차종을 누르면 현재 가속·제동·조향·사이드 브레이크 입력을 비우고 새 PlaySession ID로
WebSocket 연결을 교체한다. 서버는 새 주행 lifecycle을 출발점에서 초기화한다. 현재 선택된
차종을 다시 누르면 불필요한 reset을 만들지 않는다.

통신 규격에는 `SimulationReset.requested_vehicle_class`를 추가했다. 서버는 요청값을
검증하고 reset fingerprint에 포함하며, 값이 없는 기존 client는 세단으로 처리한다. 같은
PlaySession으로 재연결할 때는 기존 차종과 자세를 보존하고, 같은 세션에서 차종만 바꾸는
요청은 거부한다. Unreal의 명시적 차종 변경은 새 PlaySession을 사용하므로 이 계약을
우회하지 않는다.

서버는 세단 기본 설정에서 차종별 전체 Ego profile을 만들고 lifecycle 경계에서 물리
parameter를 교체한다. 질량, wheelbase, 조향각·조향 속도, 구동·후진 힘과 출력, 제동력,
공기저항, 타이어 반지름, 최고속도, 윤거, 무게중심, 차체 관성, 타이어 강성·마찰,
서스펜션과 충돌 외곽을 차종별로 사용한다. 적용된 차종은 Ego의 권한 `WorldState`로 다시
보내며 Unreal은 이 값을 받은 뒤에만 차체, 바퀴 위치·크기·표시 수, 램프, 클락션과
배기가스 위치를 바꾼다. 따라서 화면에서만 다른 차로 바뀌고 서버 물리는 세단으로 남는
상태를 허용하지 않는다.

구 서버와 조용히 어긋나는 경우도 막았다. Unreal은 서버 Hello에서
`player-vehicle-selection.v1`을 필수로 확인하며, 해당 기능이 없는 서버에는 reset을 보내지
않는다. 차종 변경으로 PlaySession이 바뀌면 SensorRig의 sequence와 센서별 capture cadence를
초기화한다. 권한 physics replay의 RESET과 Unreal 주행 CSV v2에도 차종을 기록해 재생 때 같은
profile과 외형을 사용한다. 기존 physics replay의 차종 없는 RESET과 CSV v1은 세단으로 읽어
호환한다.

오토바이는 화면에서 앞·뒤 바퀴 두 개를 표시하지만, 현재 물리는 네 접점과 네 서스펜션을
사용하는 reduced-order 차량 profile이다. 실제 이륜차의 기울기, 조향에 따른 균형과 전복
복원까지 구현한 모델은 아니다. 세단 외 차체도 현재 기능 검증용 authored mesh이며,
세단용 실내와 운전자 표현을 그대로 잘못 끼우지 않도록 비활성화한다.
