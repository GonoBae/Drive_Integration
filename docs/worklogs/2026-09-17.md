# 2026-09-17 검토 후속 작업

프로젝트 검토에서 나온 여섯 항목을 순서대로 보완했습니다. 기존 미커밋 변경과 에셋은
보존했고, 이번 작업에서 새 기능 확장이나 차량 물리 재설계는 하지 않았습니다.

## 1. 조금씩 누적되는 입력 지연

기존 ControlLease는 직전 수락 패킷과의 시간 차이만 비교했습니다. 10ms 간격으로
만든 입력이 100ms 간격으로 도착하면 매번 90ms로 판단하여, 실제 누적 지연이 100ms를
넘어도 제어권을 갱신할 수 있었습니다. 이 경우를 새 테스트로 먼저 실패시킨 뒤 수정했습니다.

세션에서 관찰한 가장 신선한 시점 대비 지연을 누적하고, 입력이 따라잡으면 줄입니다.
거절한 입력은 sequence·수신 시각·지연 기준을 갱신하지 않습니다. 재연결·새 Play에서는
지연 기준을 초기화합니다. 100ms 경계, 정상 복귀, 새 시계 기준의 재연결도 검사합니다.
양쪽 절대 시계를 동기화하거나 첫 패킷의 편도 지연을 알아내는 기능은 아닙니다.

## 2. 우회 도중 다시 막힌 NPC

활성 우회·차선 변경 중에도 지속적인 새 장애물로 0.75초 이상 정체되면 복구 판단을 합니다.
원래 경로 중심으로 순간 이동하지 않고, 현재 우회 궤적을 유지한 채 0.5m 단위로
되짚어 출발 기준점에 돌아온 다음 계획을 해제하고 다시 판단합니다.

중앙선 침범 금지, 뒤쪽 차체 경로·1m 여유, 일반 6m·사고 16m 후진 한도를 유지합니다.
같은 차로 안에서 기준점까지 회수할 수 없는 경우나 뒤가 막힌 경우에는 사유를 남기고
대기합니다. 신호 대기·짧은 일시 정체·차량 손상 정지를 무조건 후진으로 바꾸지 않습니다.
장애물이 사라지면 진행 가능한 기존 경로를 다시 따릅니다.

이 기능은 임의 위치에서 어떤 상황이든 탈출하는 전역 경로계획이 아닙니다. 교차로 연결을
거슬러 올라가거나 후진 한도를 넘는 복구는 하지 않습니다. 실제 화면에서의 자연스러움은
별도 확인 대상입니다.

## 3. 탐색 준비 비용과 전체 처리 시간

기존 48작업 제한은 지면·예측 검사 횟수의 제한이며 전체 서버 시간의 제한이 아닙니다.
장애물 장면 준비 시간과 형상 수를 별도로 공개하고, 전체 탐색 조각 시간에는 성공 직전
최종 안전 검사까지 포함합니다. 신규 밀집 장면 회귀는 준비 작업이 포함되면서도 기존
작업량 제한과 새 Play 초기화가 유지되는지 확인합니다.

측정값은 머신 속도에 영향을 받으므로 자동 테스트에 임의의 ms 합격선을 넣지 않았습니다.
대규모 맵에서 전체 장애물 순회를 제거한 것은 아니며, 실제 준비 비용이 문제가 되면
공간 색인·불변 자료 재사용을 후속으로 적용합니다.

## 4. 입력 반응을 확인할 수단

[입력 반응 측정 절차](../input_latency_measurement.md)와 분석 도구를 추가했습니다.
실제 키와 화면을 함께 촬영한 120fps 이상 원본에서 가속·제동·좌/우 조향을 각각
10회 이상 확인합니다. 양 끝점의 오차를 더한 최대 상한으로 50ms를 판정합니다.
무응답·판독 불가를 빼고 계산하지 않으며, 영상·실행 파일·패키지 식별값을 보존합니다.

이것은 물리 키→화면 반응의 수동 종단 측정입니다. 서버 적용 ACK 지연이나 30분 FPS
결과가 아니며, 도구의 합성 테스트 통과도 실제 입력 반응 측정 통과가 아닙니다.

## 5. 배포 후보 식별

manifest v2에 소스 revision·dirty 여부, 미추적 파일을 포함한 빌드 입력 해시와
배포 파일 전체 해시를 기록합니다. 빌드 중 입력이 변경되면 후보 생성을 실패 처리합니다.
패키지 실행 검사는 파일 무결성부터 확인합니다. 기존 검사 보고서는 생성 전 참고 자료로
명시하여 복사하며 패키지 주행 인수로 바꿔 쓰지 않습니다.

`StartClient.ps1 -PerformanceCapture`로 10초 준비 후 30분 frame/state 캡처를 시작할 수
있습니다. VSync·프레임 제한은 자동 변경하지 않으며 사람이 조건을 확인해야 합니다.
`source_snapshot.json`은 소스 백업이 아닙니다. 9/17 검증 당시에는 커밋·푸시를 수행하지 않았고, 정식 공유 전
필요한 신규 파일까지 커밋하여 그 revision을 다시 빌드하는 작업은 별도입니다.
