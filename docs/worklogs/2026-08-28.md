최종 wheel contact sample의 per-corner authored-surface coverage mask를 사용한다.

| coverage 상태 | 처리 |
|---|---|
| 한 corner만 miss, 나머지 3개 hit | partial support 계속 계산 |
| 대각선으로 마주 보는 2개 hit | partial support 계속 계산 |
| front axle 두 ray miss | 이전 지원 step으로 fail-close, 속도 0 |
| rear axle 두 ray miss | 이전 지원 step으로 fail-close, 속도 0 |

| right side 두 ray miss | 이전 지원 step으로 fail-close, 속도 0 |

## Bake 후 수동 서버 재시작 제거

### 원인

exporter는 ground·static CSV를 교체하고 manifest를 마지막에 commit했지만 host는 시작 시에만
MapPackage를 읽었다. 실행 중 Bake하면 Unreal 로컬 checksum과 서버의 authoritative checksum이
달라져 control이 fail-closed했고, 서버를 재시작해야만 다시 움직였다. 이는 안전 동작이기는
했지만 편집 반복 과정에는 잘못된 운영 계약이었다.

### 구현

- `MapPackageHotReloader`가 `manifest.cfg`를 250ms 주기로 백그라운드 감시한다.
- ground, static collision, payload checksum과 최종 manifest checksum을 모두 검증한 후보만
  simulation thread로 전달한다. 작성 중·불완전·잘못된 후보는 기존 snapshot을 손상시키지
  않고 거부한다.
- 여러 후보가 연속 도착하면 가장 최신의 완전 검증된 후보만 남긴다.
- host는 고정 tick 시작점에서 ground·collision·checksum을 한 번에 교체하고 차량 spawn,
  simulation clock cadence, control lease/lifecycle과 demo entity를 새 map 기준으로 reset한다.
- 이전 WebSocket을 의도적으로 닫아 stale session을 차단한다. Unreal은 모든 재연결에서 로컬
  manifest를 다시 검증하고 checksum이 달라졌다면 새 `PlaySessionId`로 자동 Reset handshake를
  수행한다.
- 동일 payload를 다시 Bake해 checksum이 바뀌지 않으면 reload하지 않는 것이 정상이다.

### 자동 검증

- startup/watch 경쟁, manifest-last invalid→valid, 후보 1회 전달, latest-wins를 전용 시험으로
  검증했다.
- tick-boundary 원자 교체, ground·static/runtime entity 교체, clock cadence 재시작, 이전
  checksum 거부, 새 checksum의 fresh reset 전 control 거부와 reset 후 허용을 검증했다.
- 같은 PID `11152`에서 Wall/Broad fixture를 현재 Landscape checksum

## Unreal 지면 측정과 C++ 물리 계산 책임 분리

### 문제

지면 hit 측정은 이미 Unreal exporter가 담당했지만 결과를 `ground_surface.csv` triangle로만
교환했다. 약 500m full bounds를 20,000 triangle 제한에 맞추면서 spacing이 507cm로
자동 상승했고, 급경사·요철·wheel contact에 필요한 형상이 사라졌다. 서버가 지면을
측정한 문제가 아니라 Unreal 측정 결과의 표현과 concrete triangle loader 결합이 원인이었다.

### 구현

- 신규 Unreal `SimCoreGroundSnapshot`이 `WorldStatic`을 vertical LineTraceMulti로 측정한다.
  각 sample에 ENU 높이와 `ImpactNormal`, valid flag를, 각 cell에 drivable flag를 기록한다.
- 새 `SIMGHF1` binary는 80-byte little-endian header, row-major 20-byte sample과 4-byte cell
  record를 사용한다. sampling actor yaw는 ENU column/row step vector로 보존한다.
- 기존 actor에 저장된 507cm 값을 재사용하지 않도록 새
  `HeightfieldSampleSpacingCm=100` property를 도입했다. 최대 2,000,000 samples를 넘으면
  exporter가 resolution을 자동 저하하지 않고 명시적으로 실패한다. 현재 506m급 bounds는
  약 `507×507=257,049` samples, 5.9MiB로 예상된다.
- manifest v1을 유지하기 위해 `ground_surface.csv`는 comments+strict header만 가진
  sentinel로 쓰고 `collision_files`에 `ground_heightfield.bin`을 추가한다. 구 host는 empty
  triangle source를 거부하므로 거친 지면으로 조용히 fallback하지 않는다.
- exporter는 sentinel·binary·static CSV를 모두 staging/replace한 뒤 manifest를 마지막에
  commit한다. 성공 창의 수동 서버 재시작 지시는 제거하고 기존 hot reload/tick-boundary
  apply와 PIE 새 session reset을 안내한다.
- C++ `RuntimeMapPackage`는 concrete `MapPackageGroundQuery` 대신
  `shared_ptr<const GroundQuery>`를 소유한다. binary가 선언되면 새
  `HeightfieldGroundQuery`, 아니면 legacy triangle provider를 선택한다.
- heightfield query는 affine basis를 역변환해 cell을 O(1)로 찾고 기존 exporter와 같은
  P00/P10/P11 또는 P00/P11/P01 diagonal에서 height와 Unreal 측정 normal을 보간한다.
  magic/version/stride/크기/overflow/finite value/normal/basis/flags/invalid reference/no-ground를
  fail-closed한다.

상세 결정은 [ADR-012](../decisions/ADR-012-unreal-ground-measurement-boundary.md)에 기록했다.

## 자동 P2 선행 통합 결과

일정상 5~7시간으로 잡았던 좌표·통신·진단·외부 설정 범위를 같은 날 자동 선행 통합했다.
완료 근거와 아직 남은 수동 경계를 다음처럼 분리한다.

- 지면 snapshot writer와 C++ loader/query를 `SIMGHF2`로 확장해 cell별 stable material ID와
  terrain friction multiplier를 전달한다. C++ 차량 물리는 tire friction, terrain
  multiplier, vehicle profile scale을 결합하며 strict vehicle config는 format v5의
  default/asphalt/low-friction/rough scale을 읽는다. `SIMGHF1`은 default material·1.0
  multiplier로 계속 호환한다. v2 fixture의 export 계약→strict load→contact material→tire
  force 경로는 자동 시험을 통과했다.
- 실제 tracked `ground_heightfield.bin`은 앞 절의 15:22 Bake 결과인 `SIMGHF1`이다. 따라서
  실제 Landscape의 Physical Material/tag를 담은 v2 재Bake와 PIE 마찰 체감은 아직 수동
  gate이며, 이를 이미 통과한 것으로 표시하지 않는다.
- C++ `GeoTransformAdapter`와 UE `SimCoreCoordinateFrames`가 ENU/FLU↔UE FRU position,
  polar/axial vector, quaternion basis 계약을 공유한다. UE 5.6 headless Automation
  `DriveIntegration.Coordinates.GeoTransformContract` 1/1이 `Success`로 끝났다. 실제 Cesium
  geodetic origin, SensorRig frame과 Landscape PIE 시각 확인은 후속이다.
- 서버와 UE가 ordinary reset/control/state 전에 양방향 `Hello`를 교환한다. 양쪽 모두
  schema version, source/build identity, MapPackage checksum과 필수 capability를 strict하게
  검사하며 불일치와 빈/중복 capability는 fail-closed한다. transport는 첫 client Hello가
  승인되기 전 WorldState broadcast를 차단하고 거부 시 1008 policy close한다. 승인된
  Hello의 build/schema/map checksum/sorted capability set은 negotiated fingerprint로 고정하고,
  connection generation에는 source/session/highest sequence를 결속한다. 같은 sequence는
  message kind와 sequence를 제외한 semantic payload가 완전히 같은 재전송일 때만 idempotent하게
  허용한다. 거부된 높은 sequence는 high-water를 오염시키지 않는다. 로그 경계 identity는
  printable ASCII만 허용하며 기본 listener는 `127.0.0.1` 전용이다. 첫 frame 1008 close가
  peer 응답이나 write 정체로 끝나지 않으면 250ms grace 뒤 TCP를 강제 종료한다. E-stop만
  초기화 전 안전 예외다.
- UE 경량 diagnostics HUD는 connection, hello, map, control gate, state rate, sequence,
  local/server age, max gap, forward sequence `missing`, duplicate/out-of-order `old`, 짧은
  checksum과 controlled entity를 표시한다.
  authoritative SafeStop/Health 표시는 아직 구현하지 않았다.
- C++ 실행 설정은 strict `runtime_server.cfg`와 CLI override로 외부화했다. 우선순위는
  built-in defaults &lt; cfg &lt; CLI이며 WebSocket port, physics Hz, origin lat/lon/alt,
  spawn heading, command/queue/hard timeout, source ID, demo entities와 vehicle/map 경로를
  검증한다. unknown/duplicate/missing value, non-finite/range/cross-timeout 오류는 시작을
  거부하고 `--help`를 제공한다.
- 최종 Windows C++ Release 전체 build와 CTest **14/14**, 전체 suite 20회 **280/280**
  (**48.35s**), UE 5.6 Editor/Game build, headless Automation **1/1**이 통과했다. 최종
  `cpp/host/build/Release/simcore_publisher.exe`는 **1,045,504 bytes**, LastWrite
  **2026-08-28 16:33:12.283**, SHA-256
  `B624E762E6200F961E9901CC42A9C419ED090C06B167CF06DDF0129F128E7EF3`다.

### 실제 Hello fail-closed/정상 경로 smoke

- 최종 executable을 PID `6648`로 시작했고 `127.0.0.1:9000` localhost listener를 확인했다.
  stdout은 `runtime_logs/simcore-landscape-20260828-163503.stdout.log`, stderr는
  `runtime_logs/simcore-landscape-20260828-163503.stderr.log`다.
- invalid Hello는 첫 application payload를 승인하지 않고 close code 1008로 종료했으며,
  client Hello 승인 전에는 WorldState가 한 건도 노출되지 않았다.
- 승인된 generation에서 같은 sequence를 다른 semantic payload로 재사용한 두 시도는 모두
  거부됐다. 이 실패가 high-water를 오염시키지 않아 뒤이은 valid recovery에서
  `WorldState` sequence **5148**, checksum `fnv1a64:b8b0a6ccd89614de`, entity **1개**를
  실제 수신했다.

## 남은 수동 게이트

새 100cm v1 payload의 실제 Bake와 첫 동일 PID hot reload, v2 재질/마찰 자동 계약은
완료됐다. 다음 항목은 아직
완료로 표시하지 않는 사용자 환경 수동 gate다.

1. 실행 중인 서버 PID를 유지한 채 PIE에서 전후진·A/D 조향·경사·요철 진입을 확인한다.
   네 wheel 접지, 차체 z·pitch·roll, 지면 관통·부유·terminal edge 정지를 함께 본다.
2. 약 5m/s full A/D에서 4~6.5m, 약 10m/s에서 15~25m 수준의 선회 envelope와 저속
   횡미끄러짐이 없는지 체감 확인한다.
3. PIE를 정지하고 Landscape를 조금 Sculpt하고 Physical Material/tag를 지정한 뒤 v2로
   다시 Bake한다. payload가 바뀌었다면 서버
   `[MapReload]` 두 단계 로그와 Unreal의 짧은 disconnect→reconnect→새 session reset을
   확인한다. 프로세스를 재시작하지 않는다.
4. 실제 벽·커브 gate는 marker를 배치·Bake해 `static_colliders>0`으로 만든 뒤 비관통을
   확인한다. 현재 package의 `static_colliders=0`이므로 WP-03 전체 완료로 표시하지 않는다.

## 일정 감사

- AI 병행 작업을 반영한 현재 Core 기준 완료일은 2026-09-07, Should 확장 기준은
  2026-09-11이며 2026-08-28 현재 이 재계획 대비 확정 영업일 지연은 0일이다.

  누적된 물리·지형 안정화 범위와 수동 검증 미완료를 숨기지 않기 위한 별도 비교값이다.
- 이번 hot reload·조향·통신 반복 안정화와 자동 P2 5~7시간 선행으로 오늘 최우선 자동
  작업은 완료했다. 남은 Core는
  static collision 수동 gate, 경사/차체 자세 PIE gate, LaneGraph·traffic·SensorRig/replay·
  성능 검증을 포함해 약 33.5~49시간이다. 8/31~9/7 가용 48시간을 초과하는 최악 경우에는
  9/8 buffer가 필요하다.
- 날짜를 앞당기기 위한 세 흐름 중 A의 GeoTransform·quaternion·Hello/HUD·외부 설정 자동
  범위는 완료했다. B는 LaneGraph schema/importer와 신호·traffic 상태기계 기반, C는
  SensorRig frame metadata와 recorder/replay 골격이다. 공통 schema와

- 조건부 선행 달성 목표는 **9월 4일 Core RC 인수 후보**다. 9월 3일까지 자동 Core 후보와
  전체 자동 회귀를 만들고 9월 4일 목표 PC PIE·30분 시험을 통과하면 관리 완료일을

## 모델 범위

현재 차량은 네 독립 1D suspension, wheel rotational inertia와 sprung-body
heave/pitch/roll을 결합한 ground-bound reduced-order 모델이다. terminal footprint
fail-close는 이 모델의 적용 범위를 명시하는 안전 정책이며, 실제 절벽 낙하·jump·airborne·
전복을 계산하는 full 6DoF 대체물이 아니다.
