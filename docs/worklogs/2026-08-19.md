# 2026-08-19 D6 작업 로그

## 목표

- D3에서 남은 고정 시계와 입력 안전 경로 회복
- D5/D6 차체 상태와 바퀴·타이어 기반 구현
- C++·Python·Unreal 공통 상태 계약과 Windows 검증

## 구현

- 상대 timer를 절대 deadline 기반 `SimulationClock`으로 교체하고 overrun을 계측했다.
- command source 소유권, sequence 역순·중복 거부, map checksum 검사와 E-stop latch를 추가했다.
- 마지막 유효 명령이 250ms를 넘으면 throttle을 해제하고 full brake·handbrake SafeStop을 적용한다.
- `EntityState`에 3D ENU 위치, body 선·각속도, 4개 `WheelState`를 후방 호환 필드로 추가했다.
- 4개 바퀴의 평면 접촉점, normal load, 조향각, angular speed, slip angle과 종·횡력을 계산한다.
- 휠 관성과 longitudinal slip 기반 종력, slip angle 기반 횡력을 계산하고 friction circle로 제한한다.
- 종·횡 하중이동, 후륜 구동, 4륜 제동, yaw 관성, roll/pitch spring-damper 응답을 계산한다.
- Unreal wire adapter가 새 상태를 파싱하고 임시 wheel mesh의 조향·회전을 표시한다.
- Python relay 생성물과 JSON observer 출력을 새 계약에 맞췄다.
- WebSocket accept 완료 전 state frame이 전송되던 경쟁 상태를 차단해 HTTP 101 핸드셰이크 순서를 보장한다.
- Windows host가 실행 중 1ms timer resolution을 요청해 60Hz state 전송의 30~50ms 간헐적 지연을 제거했다.
- Unreal은 입력 변화를 즉시 전송하고, 최신 body velocity와 state 수신 시각으로 최대 50ms dead reckoning을 적용한다.
- UE 5.6의 약 30Hz libWebSockets service에 60Hz heartbeat를 넣어 command FIFO가 누적되던 원인을 확인했다.
- Windows WebSocket을 event-loop service로 전환하고 heartbeat를 20Hz로 낮춰 변화 입력이 오래된 반복 명령 뒤에서 기다리지 않게 했다.
- PIE background CPU throttling을 꺼 3FPS 저하, 330ms command gap과 250ms SafeStop 반복을 방지했다.
- Unreal state telemetry에 수신률, server/local age, 최대 packet gap과 오래된 sequence drop 수를 추가했다.

## 문제 해결 사례

서버 수신 이후 지연만 측정하면 빠르게 보이지만 실제 키 입력은 UE 내부 송신 FIFO에서 대기하고 있었다. 60Hz producer와 약 30Hz consumer의 차이로 지연이 시간에 비례해 증가한 사례와 재발 방지 기준은 [UE 5.6 WebSocket 입력 지연 누적 해결 사례](../troubleshooting/ue56-websocket-growing-input-delay.md)에 정리했다.

## 남은 한계와 다음 작업

- 현재 wheel contact는 z=0 평면이며 MapPackage 높이·법선 raycast가 아니다.
- roll/pitch는 suspension-equivalent 응답이며 바퀴별 spring/damper stroke는 아직 없다.
- D7에서 차량 파라미터 외부 파일, 경사면, 실제 suspension, 반복 튜닝 시험을 진행한다.

## 종료 전 재검토 보완

- timeout 때 source와 sequence를 초기화하던 경로를 session 기반 `ControlLease`로 교체했다.
- command의 client monotonic time과 server 수신 간격 차이로 queue age를 추정하고, 100ms를 넘긴 지연 패킷이 SafeStop을 해제하지 못하게 했다.
- timeout session을 폐기하면서 기존 WebSocket도 닫고, Unreal이 0.5초 후 새 session으로 자동 재연결하도록 해 소켓 큐 자체를 안전 경계 밖으로 제거했다.
- Proto `Envelope`에 연결별 `session_id`를 추가하고 Unreal과 Python 생성물을 동기화했다.
- 공개 body frame을 X=forward, Y=left, Z=up으로 통일하고 C++ 내부 Y=right 값은 publish 경계에서 변환했다.
- 우회전 시 바깥쪽 왼쪽 바퀴가 가중되도록 횡하중 이동 부호를 수정하고, 전·후축에 전체 질량을 중복 적용하던 계산을 50/50 axle mass로 수정했다.
- Unreal axis 입력은 deadzone/epsilon 처리 후 동일 frame의 최신값 하나만 최대 30Hz로 전송한다.
- Unreal WorldState parser가 첫 엔티티가 아니라 설정된 `ControlledEntityId`를 끝까지 찾아 선택하도록 수정했다.
- macOS Release 빌드, C++ 시험 6종, Python Proto import와 의존성 검사를 통과했다. Unreal 소스는 현재 Mac에 UE 5.6 toolchain이 없어 다음 Windows 실행 시 Game/Editor target을 다시 빌드해야 한다.

## 좌표계 결정과 후속 작업

- 공통 공개 좌표는 ROS REP-103 호환 right-handed FLU(`X=forward, Y=left, Z=up`)를 유지하기로 결정했다.
- Unreal의 left-handed FRU(`X=forward, Y=right, Z=up`)와 현재 C++ solver 내부 FRU는 공개 계약이 아니라 경계 adapter가 변환하는 runtime 구현으로 한정한다.
- 현재 완료된 범위는 공개 body 선·각속도 vector와 wheel slip/lateral force의 Y-left 변환 및 기본 C++ 회귀다.
- 아직 완료되지 않은 범위는 legacy scalar `yaw_rate`, `steering_angle`, `ControlCommand.steering`의 좌회전/좌조향 양수 이행, schema 호환 차단, 전용 `BodyFrameAdapter`·`GeoTransformAdapter`, polar/axial vector·quaternion·heading 회귀, sensor frame metadata, 목표 Windows UE 시각 검증이다.
- 위 작업은 [ADR-011](../decisions/ADR-011-canonical-coordinate-frames.md)의 `COORD-002~008`로 식별하고 D7(C++/Proto), D9(Unreal), D11(Sensor/Recorder) 일정 게이트에서 추적한다.

## 전체 코드 리팩터링

- C++의 실행 조정을 `SimulationHost`로 분리하고 `main.cpp`는 플랫폼 timer와
  WebSocket/ZMQ 조립만 담당하도록 축소했다. 물리·프로토콜·transport도 재사용 가능한
  CMake library target으로 나눴다.
- `ControlLease`는 모든 검증이 끝난 뒤에만 sequence/clock 상태를 확정하며,
  `SimulationClock`은 놓친 deadline을 건너뛰어 catch-up 폭주를 막는다.
- WebSocket은 handshake 전 종료, 64KiB 수신 제한, server stop과 비동기 수명을
  명시적으로 처리한다. 초기·발행 wheel contact는 같은 post-integration pose를 쓴다.
- 최고속도에서 차체만 clamp되어 구동륜 각속도가 계속 누적되던 경로에 방향별
  torque cut을 적용하고 전진·후진 100초 포화 회귀시험을 추가했다.
- Unreal client는 연결 상태와 socket generation을 구분하고, callback 데이터를
  소유 복사한 뒤 game thread에서만 적용한다. 좌표 변환과 표시 sampling은
  `SimCoreCoordinateFrames`와 `SimCorePresentation`으로 분리했다.
- Python relay는 저장소 루트에서 `python -m python.relay_server`로 실행하며,
  lifespan 종료 시 subscriber cancel/await와 DB close를 보장한다. malformed Proto,
  느린 WebSocket, DB 오류는 서로 격리하고 상태를 health 응답에 노출한다.
- relay 전송 timeout 클라이언트는 목록에서만 제거하지 않고 close code 1013으로
  종료하여 상대가 열린 zombie 연결로 오인하지 않고 재연결할 수 있게 했다.
- macOS에서 C++ Release 빌드와 CTest 6/6, Python unittest 14/14, Proto 생성물
  동기화와 의존성 검사를 통과했다. Unreal 변경은 정적 API 검토만 통과했으며
  Windows UE 5.6 Game/Editor target 재빌드를 최종 게이트로 남긴다.
