# 2026-08-19 D6 작업 로그

## 목표

- D3에서 남은 고정 시계와 입력 안전 경로 회복
- D5/D6 차체 상태와 바퀴·타이어 기반 구현
- C++·Python·Unreal 공통 상태 계약과 Windows 검증

## 구현

- 상대 timer를 절대 deadline 기반 `SimulationClock`으로 교체하고 overrun을 계측했다.
- command source 소유권, sequence 역순·중복 거부, map checksum 검사와 E-stop latch를 추가했다.
- 마지막 유효 명령이 250ms를 넘으면 throttle을 해제하고 full brake·handbrake SafeStop을 적용한다.
- `EntityState`에 3D ENU 위치, body 선·각속도, 4개 `WheelState`를 후방 호환 필드로 추가했다.
- 4개 바퀴의 평면 접촉점, normal load, 조향각, angular speed, slip angle과 종·횡력을 계산한다.
- 휠 관성과 longitudinal slip 기반 종력, slip angle 기반 횡력을 계산하고 friction circle로 제한한다.
- 종·횡 하중이동, 후륜 구동, 4륜 제동, yaw 관성, roll/pitch spring-damper 응답을 계산한다.
- Unreal wire adapter가 새 상태를 파싱하고 임시 wheel mesh의 조향·회전을 표시한다.
- Python relay 생성물과 JSON observer 출력을 새 계약에 맞췄다.
- WebSocket accept 완료 전 state frame이 전송되던 경쟁 상태를 차단해 HTTP 101 핸드셰이크 순서를 보장한다.
- Windows host가 실행 중 1ms timer resolution을 요청해 60Hz state 전송의 30~50ms 간헐적 지연을 제거했다.
- Unreal은 입력 변화를 즉시 전송하고, 최신 body velocity와 state 수신 시각으로 최대 50ms dead reckoning을 적용한다.
- UE 5.6의 약 30Hz libWebSockets service에 60Hz heartbeat를 넣어 command FIFO가 누적되던 원인을 확인했다.
- Windows WebSocket을 event-loop service로 전환하고 heartbeat를 20Hz로 낮춰 변화 입력이 오래된 반복 명령 뒤에서 기다리지 않게 했다.
- PIE background CPU throttling을 꺼 3FPS 저하, 330ms command gap과 250ms SafeStop 반복을 방지했다.
- Unreal state telemetry에 수신률, server/local age, 최대 packet gap과 오래된 sequence drop 수를 추가했다.

## 문제 해결 사례

서버 수신 이후 지연만 측정하면 빠르게 보이지만 실제 키 입력은 UE 내부 송신 FIFO에서 대기하고 있었다. 60Hz producer와 약 30Hz consumer의 차이로 지연이 시간에 비례해 증가한 사례와 재발 방지 기준은 [UE 5.6 WebSocket 입력 지연 누적 해결 사례](../troubleshooting/ue56-websocket-growing-input-delay.md)에 정리했다.
