# 2026-09-02 작업일지 — 차량 시청각 표현과 연석 지지면 정합

> 이 문서는 당일 진행 순서대로 이전 실행 증거를 보존한다. 현재 최종 상태는 문서 끝의
> **최종 통합 업데이트**를 기준으로 한다.

## 결과 요약

코드 기반 운전 계기판, 배기가스, 엔진·타이어 소리를 `AExternalVehiclePawn`에 통합했다.
모두 서버의 fresh authoritative 차량 상태를 읽는 presentation-only 소비자이며 물리·제어·
protocol에는 값을 되먹이지 않는다. 동시에 보도 지지면이 연석 top보다 8cm 낮아 바퀴가
파묻혀 보이던 저장 맵 오류를 수정하고 실제 `virtual_city_v1`을 다시 Bake했다.

자동 검증과 UE 5.6 `-game` 오프스크린 실행은 통과했다. 사용자 PIE에서 음량·음색,
배기 위치/농도, HUD 가독성, 위치·각도별 연석 승월감을 확인하는 수동 인수는 남아 있다.

## Unreal presentation

### 운전 계기판

- `ASimCoreInstrumentClusterHud`를 기본 GameMode의 `HUDClass`로 자동 설치했다.
- authoritative 속도(km/h), RPM, 기어, 연료를 표시한다.
- `LIVE`, `STALE`, `RECONNECTING`, `OFFLINE`, `INCOMPATIBLE` 상태를 구분하며 stale 시
  이전 수치를 `---`로 즉시 지운다.
- 주차 브레이크는 서버 확인값이 아직 없으므로 로컬 command intent임을 분리했다.
- Blueprint·외부 UI 에셋 없이 16:9 하단 중앙 Canvas로 구성했다.

주요 파일은 `SimCoreInstrumentCluster.h/.cpp`, `SimCoreInstrumentClusterTests.cpp`,
`DriveIntegrationGameModeBase.cpp`다.

### 엔진·타이어 소리

- `USimCoreVehicleAudio` procedural synth를 추가했다.
- 엔진음은 authoritative RPM, 노면/마찰음은 차속·접지·하중·종슬립·슬립각·휠 각속도를
  읽는다. 비접지 타이어는 마찰음에 포함하지 않는다.
- stale/disconnect/PIE 종료에서는 감쇠 후 무음으로 전환한다.
- 외부 오디오 파일이나 물리 SDK를 추가하지 않았다.

주요 파일은 `SimCoreVehicleAudio.h/.cpp`, `SimCoreVehicleAudioTests.cpp`이며 Build.cs에
`AudioMixer`를 추가했다.

### 배기가스

- `USimCoreExhaustComponent`가 Engine 기본 particle material과 transient CPU sprite graph를
  코드로 생성한다. 최대 draw count는 48개다.
- RPM과 종가속도로 idle 흐름과 부하 시 밀도를 계산하고 stale에서는 새 입자를 0으로 감쇠한다.
- 위치는 차량 로컬 `(-221, 55, -25)cm`의 우측 후방 tailpipe 기준이다.

첫 오프스크린 `-game` 검증에서 Cascade 저작 helper인 `SetToSensibleDefaults()`가
`GIsEditor` assertion을 일으키는 실제 런타임 결함을 찾았다. Editor 전용 helper를 제거하고
LOD·required/spawn·lifetime·size·velocity·color 모듈을 transient runtime object로 직접
구성하도록 수정했다. 이후 같은 `-game` 실행과 screenshot 저장이 exit 0으로 통과했다.

주요 파일은 `SimCoreExhaustComponent.h/.cpp`, `SimCoreExhaustTests.cpp`다.

## 연석에서 바퀴가 파묻혀 보인 문제

### 원인과 수정

연석 top은 0.24m였지만 첫 support 이행의 보도 top은 0.16m였다. 바퀴가 연석을 넘은 뒤
8cm 낮은 보도에 정착하면서 타이어 옆면이 연석 mesh와 겹쳤다. `AddSidewalk`를 연석과 같은
0.24m support로 정렬하고 `CurbSidewalkTopAlignment` Automation을 추가했다.

저장 맵에는 `BuildVirtualCity -SyncSidewalkCurbHeight` 제한 migration을 적용했다. 116개
보도가 정확한 legacy 또는 canonical transform인지 전체 preflight한 뒤 legacy component만
8cm 올리고 저장·Bake·재로드·엄격 검증했다. 편집된 component가 있으면 변경 전에 거부한다.

50cm heightfield의 road-side near sample이 cell 대각선에서 수 cm 낮아지는 경우는
최대 `0.30R`까지만 허용했다. collider 높이는 계속 `0.75R` 이하여야 하며, far plateau가
같은 쪽으로 상승하고 collider 높이와 `0.30R` 안에서 일치해야 한다. 2.88cm undershoot는
통과하고 10cm undershoot는 차단하는 synthetic 회귀를 추가했다. Wall·Barrier·unknown과
높은 턱은 계속 fail-closed다.

## signal_city_v2 다중 교차로 확장

기존 `L_VirtualCity`/`virtual_city_v1`을 보존하면서
`/Game/SignalCity/Maps/L_SignalCity`와 `map_packages/signal_city_v2`를 별도로 생성했다.
비정형 외곽 loop와 중앙 avenue가 두 교차로를 연결하고, traffic format version 2의
독립 controller plan·offset을 서버 simulation clock으로 계산한다. 실행과 재생성 절차는
[signal city 빠른 시작](../signal_city_quickstart.md), package 경계는
[package README](../../map_packages/signal_city_v2/README.md)를 따른다.

### 구현 경계

- Unreal `SimCoreSignalCityLayout`과 `BuildVirtualCity -SignalCity`가 별도 저장 map과
  collision snapshot을 만든다. 기존 v1 map/package를 덮어쓰지 않는다.
- `SimCoreSignalCityTrafficLayout`과 `ExportVirtualCityTraffic -SignalCity`가 저장 asphalt의
  중심·좌우 폭, pole base와 collision identity를 검증하고 canonical v2 JSON을 만든다.
- C++ loader는 v1 고정 30초 주기를 그대로 보존하면서 v2 `signal_plans`, controller별
  phase·offset과 ownership을 strict 검증한다. NPC 고정 loop는 두 교차로 신호에서
  적색 정지·녹색 재출발 상태를 사용한다.
- Protobuf `TrafficSignalState`에는 additive field 7 `controller_id`를 추가했다. v1/legacy
  snapshot은 controller 1로 해석하며 Hello schema·capability 문자열은 바꾸지 않았다.
- controller ID `1..64`, group ID `1..4096`, 전체 signal ID 고유와
  `(controller, group)`별 aspect/countdown 일치를 검증한다. 같은 controller의 상충 group이
  동시에 permissive면 거부하지만 서로 다른 controller의 동시 녹색은 허용한다.
- generic v2 plan cycle 상한은 1시간이며 host serializer와 Unreal parser의 finite countdown
  상한도 3600초로 맞췄다. v1 generator의 실제 countdown은 기존 30초 이하로 유지한다.
- Unreal은 authoritative snapshot만 표시하고 stale·disconnect·잘못된 snapshot에서는
  fail-closed한다. runtime head는 `NoCollision`이며 Ego 차량을 자동 제동하지 않는다.

초기 저장 map 검증에서 collector lane 위에 직선도로 보도가 겹쳐 Raycast가 asphalt보다
높은 Rough 표면을 잡는 실제 결함을 찾았다. 네 collector 입구의 연석·보도를 12m 안쪽에서
끝내고 road slab은 유지했다. 정확한 겹침 좌표에서 최고 Ground가 Road인지 확인하는 회귀를
추가한 뒤 map/package와 traffic JSON을 다시 생성했다.

### 실행 상태와 남은 PIE 인수

PID 9604는 이 확장 전에 시작한 `virtual_city_v1` publisher의 잔존 프로세스 객체였으며,
아래 전환 전에 종료했다.
`runtime_logs/simcore-virtual-city-20260902-095714-9f725f4f.stdout.log`도
`virtual_city_v1`, 25 lanes, 3 heads를 로드했음을 보여 준다. 실행 파일이 잠겨 있던 동안
표준 build의 실행 파일을 교체하지 않았으므로, 이 프로세스를 `signal_city_v2` runtime 성공
근거로 사용하지 않는다. 대신 임시 `build_signal_city`에서 최신 publisher link와 랜덤
localhost port의 격리 Health smoke를 통과해 새 map checksum·Hello/reset·lease·reconnect
경로를 확인했고, 약 975MB의 임시 build는 검증 뒤 정리했다. 같은 최신 binary의 v2 traffic
smoke도 controller 내부 충돌 없음,
서로 다른 controller의 simultaneous permission, 새 PIE all-red, soft/hard timeout과 동일
PIE reconnect까지 통과했다.

사용자의 서버 시작 요청에 따라 stale PID 9604를 종료하고 표준 Release publisher를 최신
소스로 다시 link했다. 첫 launcher 실행에서는 PowerShell multiline `if` 문이 parse 오류를
냈으므로 동일 의미의 중첩 `if`로 수정했다. 수정된
`scripts/run_signal_city_server.ps1 -Background`는 **2026-09-02 11:25:06**에
**PID 23880**을 `127.0.0.1:9000`에 시작했다. stdout은
`runtime_logs/simcore-signal-city-20260902-112506-5abc9230.stdout.log`다. 시작 진단은 다음을
확인했다.

- map `signal_city_v2`, collision checksum `fnv1a64:7446108adad3e25b`
- traffic checksum `fnv1a64:1fb2c67092bb4aff`, lanes42, heads8
- controller 1/2 cycle36초, offset 0초/9초
- `lane_npc=enabled`, 8-lane route length 578.211m

PID는 해당 시점의 실행 증거이며 영구 상태를 보장하지 않는다. 시험 전에는 `:9000`
listener와 위 시작 로그를 다시 확인한다. 실제 사용자 PIE는 아직 완료하지 않았으므로 다음
수동 gate를 별도로 통과해야 한다.

1. 두 교차로 head의 위치·방향·가독성과 서로 다른 controller offset을 한 cycle 이상 확인한다.
2. NPC가 각 적색 정지선 전에 멈추고 녹색에 재출발해 두 교차로를 통과하는지 확인한다.
3. Ego로 외곽 loop와 중앙 avenue를 주행하며 road/lane/collision 정렬을 확인한다.
4. End PIE→Play reset, reconnect/stale all-red, 1920×1080 60fps와 30분 안정성을 확인한다.

따라서 geometry·schema·생성물과 자동 검증은 구현됐지만, `TRA-001`·`AT-05` 또는 R1 전체를
완료 처리하지 않는다. 목표 NPC 3~4대·보행자 6~8명, SensorRig·record/replay, 최종 아트와
사용자 PIE·성능 인수는 계속 남아 있다.

## 최종 통합 업데이트

위 Signal City 절 이후 차량·traffic·센서·재생 골격과 통합 회귀를 추가했다. 앞 절의
heads8·NPC1·PID23880은 그 시점의 중간 실행 증거이며 아래 최종 상태를 대체하지 않는다.

### 구현 상태

- 키보드 조향 명령은 `DeltaSeconds` 기반 상승·복귀로 바꿔 렌더 frame rate와 분리했다.
  `F3`는 collision box와 contact/force 진단을 그리는 presentation-only overlay다.
- C++ 차량은 차체 전체 chassis shell로 underside·side·roof ground contact를 해결해
  rollover 상태의 지면 관통을 막는다. 충돌 impulse에서 누적 damage/impact zone을 만들고
  Unreal은 권한 상태를 읽어 차체 변형과 impact 진단을 표시한다.
- `signal_city_v2`는 42 lanes, 신호 head 총 16개(차량8·보행8), controller2,
  server-authoritative NPC4대와 보행자8명이다. map checksum은
  `fnv1a64:7446108adad3e25b`, traffic checksum은 `fnv1a64:dfcb5e4541d71adf`다.
- SensorRig는 `base_link` FLU 기준 front camera 10Hz·roof LiDAR 20Hz config와 권한
  `SimulationTimeNs` metadata cadence를 제공한다. 실제 image/point cloud 캡처는 아니다.
- `F5`는 fresh authoritative 차량 snapshot을 CSV에 기록하며 저장 위치는
  `Saved/DriveReplays/last_drive.csv`다. `F6`는 이 상태 열을 collision-free 세단 ghost로
  재생한다. command/event를 같은 물리에 다시 입력하는 deterministic re-simulation이 아니므로
  `REC-002`·`AT-07`을 완전 완료로 판정하지 않는다.

## 사용자 주행 피드백 후속 — 사이드 브레이크, 동적 반작용, 국부 dent

사용자가 PIE에서 `F3`를 다시 눌러 overlay가 정상 토글되는 것을 확인했다. 이 입력에는
추가 변경을 하지 않았다. 이어서 Space drift, 짧은 좌우 입력의 과도한 감속, Ego가 NPC·
보행자를 밀지 못하는 현상과 차체 우그러짐 요구를 다음과 같이 반영했다.

### 조향과 rear side brake

- 키보드 A/D만 부호를 보존한 제곱 응답으로 wire 조향값을 만든다. 약 0.1초 tap은 raw
  `0.125`에서 command `0.015625`, 중앙 rack 약 `0.55°`를 요청한다. analog 입력은 선형이다.
- Space는 rear axle에만 작용하는 mechanical side brake다. 이를 누른 동안 엔진 구동력을
  무조건 0으로 만들지 않고, 뒤 타이어는 종방향 제동력을 friction circle에 먼저 배분한 뒤
  남은 범위만 횡력으로 사용한다. 앞 타이어는 service-brake가 걸리지 않으므로 조향력을
  유지하고, 뒤축 slip으로 yaw가 증가해 drift가 가능하다.
- HUD의 로컬 입력 표시는 `P BRAKE`가 아니라 `SIDE BRAKE`로 통일했다. 서버 적용 확인 필드가
  아닌 pending command intent라는 기존 경계는 유지한다.

### Ego↔NPC·보행자 충돌

- NPC OBB는 1500kg·yaw inertia 2600kg·m², 보행자 capsule은 80kg의 유한질량 proxy로
  collision solve에 참여한다. Ego와 질량비에 따른 반대 normal/tangent impulse, penetration
  correction과 속도·yaw 상한을 적용한다.
- 충돌로 바뀐 NPC·보행자의 authoritative pose/velocity를 host runtime에 되돌리고 18 tick의
  reaction hold와 감쇠를 둬 lane/crosswalk follower가 다음 tick에 즉시 원위치로 복귀하지
  않게 했다. 새 Play reset과 map/traffic reload에서는 이 반작용 상태를 지운다.
- 이번 범위는 Ego↔동적 entity다. NPC↔NPC의 완전한 차량 물리, NPC 타이어·서스펜션,
  보행자 ragdoll은 구현하지 않았다.

### 국부 차체 우그러짐

- 누적 damage의 새 event delta를 마지막 impact zone에 배분하고 전/후/좌/우/roof/underbody
  6개 weight로 보존한다. 각 구역 damage 35%에서 시각 변형 weight가 1에 도달한다.
- 세단 body material 10종에 body-local ellipsoid WPO를 추가했다. 구역별 변위를 합친 뒤
  최대 12cm로 제한하며 새 Play, sequence rewind 또는 damage reset에서 원상 복구한다.
- 이는 presentation-only dent다. 서버 collision shell, wheel pose와 ray는 변하지 않으며
  fracture·부품 분리·파편은 포함하지 않는다.

## 전체 리팩터링 체크포인트

기능 동작과 외부 계약을 유지하면서 커진 구현 파일의 책임 분리를 완료했다. C++는 runtime
options를 공개 facade·strict cfg loader·CLI parser로, traffic worker를
`TrafficNetworkHotReloader`로, Protobuf outbound serializer와 inbound decoder를 분리했다.
`SimulationHost`의 client Envelope dispatch, Hello·control·SimulationReset은
`simulation_host_session.cpp`로 옮기고 identifier validation은 session detail에 격리했다.
Unreal은 세단 asset/wheel 계약, pure control resolver, client diagnostics를 분리했고,
runtime NPC·보행자와 traffic signal presentation을 각각 별도 파일로 옮겼다. DriveReplay의
CSV/capture/sample 형식 로직과 component 수명주기·파일 I/O도 분리했다.
세 map profile의 Windows 실행 스크립트는 `server_launcher_common.ps1`의 파일·port 검증,
background log, 10초 readiness와 생성 프로세스 한정 cleanup을 공유한다.

최종 통합은 C++ Release 전체 build와 CTest **20/20**, UE 5.6 Editor/Game Development build와
전체 Automation **47/47**, Windows launcher self-test **3 profiles**, Python generated Proto
**1/1**과 smoke helper **10/10**, 격리 자식 서버의 Signal City WebSocket smoke
**2,280 states**를 통과했다. 리팩터링 중 발견한 비정상 NPC heading-rate의 partial-tick
전파를 서버 입력 clamp와 회귀로 차단해 기존 순항속도·경로 경계를 그대로 유지했다.
리팩터링 전에 사용하던 서버는 종료했으므로
위 PID들은 모두 각 시점의 실행 증거이며 현재 listener 상태가 아니다. 새 PID를 이 문서의
완료 근거로 추가하지 않는다. 상세 책임과 보존 계약은
[전체 리팩터링 구조](../refactoring.md)에 기록했다.
