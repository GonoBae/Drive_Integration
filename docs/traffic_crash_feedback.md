# 9/3 충돌·교통 피드백 확인

대상은 `/Game/SignalCity/Maps/L_SignalCity`와 `signal_city_v2`다.
서버와 UE는 동일 소스로 빌드한다. 최종 실행·자동 검사 결과는
[작업일지](./worklogs/2026-09-03.md), 지도 생성은 [빠른 시작](./signal_city_quickstart.md)을 따른다.

## 변경과 수동 확인

| 요청 | 구현 및 확인할 동작 |
|---|---|
| 차량 찌그러짐 | Ego/NPC 모두 충돌 부위의 실제 메시 정점을 변형한다. 정면 충돌 후 앞부분, 측면 충돌 후 옆부분이 눌리고 기존 손상은 유지되어야 한다. 새 Play에서 원복된다. |
| 보행자 즉시 반응 | 충격 발생 tick부터 서버의 몸통 비행·낙하·전도 상태를 표시한다. 움직이는 차량이 멈출 때까지 사람이 붙어 있으면 실패다. 팔다리는 UE PhysicsAsset 관절로 움직인다. |
| 사고 장애물 회피 | 정차 사고 차량·누운 보행자를 지속 장애물로 분류한다. 같은 방향 차선에 공간이 있으면 변경·우회하고, 양쪽 모두 막혔으면 안전하게 기다려야 한다. |
| 교통 밀도 | NPC10대, 접근부별 좌·직·우 3차로와 연결 경로를 사용한다. 노면 표시뿐 아니라 실제 NPC가 해당 차로에 진입하는지 확인한다. |
| 누운 사람의 충돌체 | `F3`에서 낮은 yaw-aligned OBB와 몸통 중심을 확인한다. 몸통은 서버 중심과 일치해야 하고 서 있는 캡슐이나 2.5m 떨어진 충돌체가 남으면 안 된다. |
| NPC와 보행자 충돌 | 실제 접촉 시 반작용·충돌 사건이 발생하며 약한 접촉은 선 채로 밀림, 강한 접촉은 전도·낙하로 구분한다. 이 충돌을 Ego의 피해로 기록하면 안 된다. 정상 신호 주행은 사고를 유도하지 않는다. |
| 깜빡이 | Ego `Q` 좌, `E` 우, `X` 비상등; 같은 키로 끈다. NPC는 서버의 회전·차선 변경 의도, 운행 불가 차량은 비상등을 표시한다. 차체에 통합한 앞·뒤 램프가 발광하고 주변을 비춘다. |
| 차로와 신호 | 좌·직·우 전용 차로를 두며 한 접근 방향의 세 이동을 함께 허용하는 보호 현시를 쓴다. 보행 전용 WALK에서는 모든 차량이 적색이다. 좌회전만 별도 녹색으로 제어하는 방식은 아니다. |

## 구현 경계

- 차체 변형은 자체 저작 세단 LOD0를 읽어 충돌 사건 때만 갱신한다. 변형·법선 계산은 정점 수에
  비례하며 원본 자산을 변형하지 않는다. 최대 변위28cm, 새 Play 복원, WPO 중복 적용 금지를 검사한다.
  금속 파괴 역학·부품 탈락이나 서버 collision shell 변형은 구현한 것이 아니다.
- 보행자는 서버의 축약 몸통 모델과 UE 부분 래그돌이다. 골반은 서버 중심을 따르고 팔다리는
  관절 시뮬레이션을 한다. 몸통 원치수 half extent는 `0.25/0.35/0.95m`, 완전히 누운 근사는
  `0.95/0.35/0.25m`다. 발·손 각각을 서버에서 정밀 충돌시키는 전신 모델은 아니다.
- NPC는 경로 추종과 유한질량 충돌을 결합한 모델이다. Ego와 동일한 네 타이어·서스펜션
  동역학이나 일반적인 도로 전체의 자유 주행 AI는 아니다.
- 자동 검사는 실제 사용자 화면·운전 감각·1080p60fps·30분 안정성 인수를 대신하지 않는다.
  이번 문서의 체크리스트는 수동 합격 선언이 아니다.

## 후속 Play 피드백: 약한 접촉·국부 손상·실제 라이트

이 절이 위의 초기 구현보다 최신이다.

- **신호등 충돌 후 패킷 오류:** UE5.6 `OnRawMessage.BytesRemaining`은 현재 프레임의 잔여
  바이트이지 전체 WebSocket 메시지의 끝이 아니다. 실제 FIN을 전달하는 `OnBinaryMessage`
  기준으로 조립한다. 메시지 크기 제한·엄격한 protobuf 검증은 유지하고 재연결 시 부분
  메시지는 폐기한다. 신호등 충돌 직후 로그의 payload/tag/schema 연속 오류와 일치하는
  분할 수신 회귀를 추가했다. 당시 패킷 바이트 자체를 확보한 것은 아니다.
- **보행자 반응 단계:** 가벼운 접촉은 서 있는 채로 밀린다. 80kg 몸통 기준 충격량120Ns
  (충격에 의한 속도 변화1.5m/s)에서 전도한다. 기존240Ns 자동 수직 발사는 아래 후속
  수정에서 제거했다. 게임 반응을 위한 조정값이며 실제 상해 판정이 아니다. 같은 사건의
  중복 수신·늦은 지속 압력으로 넘어짐을 재발생시키지 않는다. UE 래그돌은 서버 downed
  상태에만 연결한다.
- **충돌 위치별 찌그러짐:** 서버가 접촉점의 차체 좌표·힘 방향·범위·깊이를 최대16개
  patch로 보존하고 Ego/NPC 모두 proto37로 보낸다. UE는 각 작은 타원 영역만 변형한다.
  앞문 접촉이 뒷문이나 반대쪽 면까지 찌그러뜨리지 않고, 비스듬한 힘은 다른 방향·깊이로
  반영한다. 기존 면 전체 WPO는 끈다. 접촉 위치·높이는 planar 충돌과 자체 세단 skin의
  근사이며, 금속 균열·유리 파쇄·물리 collision shell의 변형은 아니다.
- **사고차 회피:** 지속 사고 장애물은 일반 적색 대기열처럼 추가 대기하지 않고 조기
  검토한다. 저속일 때 허용 차선 변경 창이8~12m 남았다면 그 안에 맞는 경로를 검토한다.
  차량 전체 외곽·지면·앞뒤 간격·다른 차의 변경 경로 검사와 합법 차선 제한은 유지한다.
  공간이 없거나 양쪽 차로가 막힌 경우에는 기다리는 것이 정상이다.
- **실제 깜빡이:** 떠 있는 별도 큐브 6개를 제거하고 기존 세단의 앞·뒤 좌우 렌즈에
  주황색 스트립을 통합했다. 렌즈 재질의 좌/우 emissive와 실제 PointLight 4개를 같이
  점멸시킨다. 조명은 짧은 범위·그림자 없음으로 제한하며 국부 차체 변형을 따라간다.
  원본과 변형 메시의 재질을 함께 갱신하므로 사고 후에도 해당 램프가 켜진다.
  Q/E/X 조작은 유지한다. 밝기·반사·주행 중 외관의 최종 합격은 Lit PIE에서 확인한다.

최종 빌드·검증·라이트 자산 갱신 결과는 [9/3 작업일지](./worklogs/2026-09-03.md)를 따른다.

## 후속 수정: 넘어진 물체·충돌 후 진행·보닛 접촉·대기 후 회피

- 쓰러져 지면에 놓인 물체만 타이어 지지 후보로 사용한다. 둥근 축약 표면과 원형
  타이어의 접촉점·법선을 구해 기존 타이어/서스펜션 계산에 공급한다. 바퀴가 올라가고
  내려오며 차체가 따라가는 처리이지, 차량 Z를 고정 이동시키는 처리가 아니다.
  반높이가 타이어 반경 이하이고 지면이 받치는 물체만 허용한다. 높거나 공중에 있는
  물체, 지면이 없는 곳, 두 바퀴 사이에서 차체 하부보다 높은 물체는 충돌을 유지한다.
- 신호등은 무한 질량 대신180kg 축약 물체와 기초부 저항을 사용한다. 한 충돌 microstep
  안에서 남은 기초부 충격량을 먼저 소진하고 잔여 충격은 유한 질량끼리 교환한다.
  먼저 차를 세운 뒤 속도를 돌려주는 방식이 아니다. 넘어지는 기둥의 이동·속도도 다음
  tick에 유지하며 바닥 마찰로 감속한다. 벽은 기존 강체 장애물로 남는다.
- 보행자의 회전은 접촉 높이에 따른 `충격량 × 질량중심까지의 팔길이 / 관성`으로
  구분한다. 하체 충격은 몸통이 차량 쪽으로 기울고, 높은 접촉은 반대 회전을 만들 수
  있다. 수평 충격에 임의의 위쪽 발사를 더하지 않는다. 보닛/유리/지붕의 축약 표면에
  몸이 위에서 닿을 때 지지하며, 차량 아래의 사람을 지붕으로 올리지 않는다.
  지지 중인 해당 차량과만 중복 평면 충돌을 제외하고 다른 충돌은 유지한다.
  UE 팔다리 초기 속도도 몸통의 선속도와 회전속도에서 계산한다.
- 사고차 뒤에서 옆 차로가 빌 때까지 기다리는 동안 조향 공간을 잃던 상황을 재현했다.
  지속 사고 장애물 앞에는8m의 변경 여유를 남겨 대기하고, 충돌 검사에 합격한 차선
  변경이 시작될 때 예약 정지점을 해제한다. 대기 원인을 서버 로그/진단에 남긴다.
  이미 범퍼까지 갇힌 차량의 후진 탈출이나 연결도로에 없는 차선을 생성한 것은 아니다.

금속 기초부 파괴, 전신 관절 충돌, 타이어에 눌리는 연체 변형까지 계산하는 모델은 아니다.
바퀴 지지는 서버의 둥근 축약 물체 모델이고, 차량 위 보행자 지지는 세단 외곽의 근사다.
GPU/Lit 외관·실제 주행 감각은 자동 검사와 별도로 Play에서 확인한다.
