# Chrono::Vehicle 10.0.0 D1 실행 결과

## 환경

| 항목 | 값 |
|---|---|
| 날짜 | 2026-08-14 |
| 운영체제 | macOS 26.5 ARM64 |
| 컴파일러 | AppleClang 21.0.0 |
| CMake | 4.3.0 |
| Chrono | 10.0.0, commit `9faf13dd8f1128dd75ed233a9627027b0422c3f7` |
| source checkout | 1.7GB |
| build tree | 1.5GB |
| 생성 shared libraries | 20MB |

## 구성

- Release shared libraries
- Chrono core, vehicle, vehicle models
- Sedan, TMeasy tire, SMC contact, rigid terrain
- Z-up, gravity -9.81m/s²
- Bullet collision system 명시
- 고정 timestep 1/600초
- 같은 결정적 입력을 3회 실행

공식 build-tree package는 Vehicle component만 요청해도 `ChronoModels_robot` 라이브러리의 존재를 검사했다. 따라서 스파이크에서는 `ChronoModels_vehicle`과 `ChronoModels_robot` 타깃을 빌드했다. 이 내용은 비교 시험 재현 환경에만 적용되며 제품 런타임에는 적용하지 않는다.

## 발견하고 수정한 문제

첫 Chrono 10 충돌 실행에서는 collision backend를 명시하지 않아 차량이 벽을 지나 최종 x=85.385m에 도달했다. `ChSystemSMC` 생성 직후 Bullet collision system을 명시하도록 수정한 뒤 위 결과로 통과했다. 외부 엔진을 다시 검토할 경우 초기화 시 collision backend를 명시하고 자동 시험으로 확인해야 한다는 근거로 남긴다.

그 밖의 8→10 API 차이는 스파이크에서 조건부로 격리했다.

- `ChVector<>` → `ChVector3d`
- `Set_G_acc` → `SetGravitationalAcceleration`
- `SetBodyFixed` → `SetFixed`
- `vehicle::VisualizationType` → `chrono::VisualizationType`
- legacy CMake 변수 → imported targets
- `add_DLL_copy_command`가 없는 package에 대한 조건부 처리

## 판정

Chrono::Vehicle 10.0.0은 개발기 기준으로 빌드, 1대·4대 주행, 충돌, 반복성 조건을 통과했다. 차량 4대 성능 여유가 작아 목표 Windows PC 재측정 없이는 성능 비교를 확정할 수 없다. 이 결과는 자체 물리 채택 이후에도 외부 엔진 비교 자료로 보존하며, 현재 제품 런타임에는 Chrono를 포함하지 않는다.
